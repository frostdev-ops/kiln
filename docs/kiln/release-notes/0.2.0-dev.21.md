# Kiln 0.2.0-dev.21 (draft)

This build fixes the dev.20 review findings, guards Library removal while the game runs, makes EML starts much cheaper, puts every Kiln hook into one registry, and helps closed-source DLL mods live next to Kiln.

## Players and server owners

- The launcher no longer removes a Library version while the game runs. Remove and Clean up say "Close Enshrouded first: the game may be reading this mod". Clean up never lists a version the game's active profile uses. This fixes the Kiln side of GitHub issue #4 (PR #5, Refs #4). The reporter's root cause is not proven.
- EML mods: a mod whose `src/mod.lua` cannot be read is switched off before the long game-data step, with the reason in `state/eml.json` and kiln.log. The other mods still run. A file that vanishes during the run drops only its own mod.
- EML starts read far less. Each game file is read at most once per start, and not at all while the OS shows it unchanged (bisdat/kiln-mods#17, whose analysis this follows). Lab server under Wine, 7.5 GiB of real server data: a start that changes nothing went from 7.6 GiB read in 5.4 s to 562 B in 64 ms. A start after a mod change went from 30.2 GiB in 13.4 s to 141.5 MiB in 1.0 s. On synthetic 55 GiB data, a cache hit went from 55 GiB read to 0 B.
- The first start after this update reads the game files once more (about 48 GiB on a client), because the old cache has no change stamps. `KILN_EML_FULL_HASH=1` turns the reuse off.
- Closed-source DLL mods (XHL-Core, Auto Loot Plus, trainers): the profile's native page has a "Load after Kiln and ShroudForge" switch per chain entry. It also shows last session's hook overlaps with a one-click fix, and the compat rules that apply.
- Chat: Kiln's chat commands keep seeing players' lines when kiln-emf or a mod hooks the same chat function first (the dev.20 high finding).
- Fedora Atomic and Bazzite (`/home -> /var/home`) no longer block ShroudForge and SET placement or modpack installs. Links inside the managed folders are still refused.
- Leftovers from dev.19 are cleaned up. A build with Nexus off gives `nxm://` links back to the handler you had before (Vortex, for example). A stray link is forwarded to it, or you get a message on how to reset the handler. A stored personal Nexus API key is removed without being shown.
- Smoother play: mod status lines never make the menu, tick or frame wait. EMF portraits are drawn off the boot thread, and current pictures skip the renderer. SET no longer re-reads a catalog without texts every 60 s, and handles non-ASCII Windows paths.
- File names that Windows would change (trailing dots or spaces) are refused in mod zips, runtime bundles and modpacks.

## Mod authors

- **kiln.hooks v2.** One registry owns one detour per game function. Every handler is a link in an ordered chain. Order: `before`/`after` constraints, then priority (higher first), then registration order. New C calls: `raw_detour` (any signature, floats too), `detour2` (up to 12 integer arguments), `mid2`, `caller()`, `call_original2`, `map_json`. See `docs/kiln/services/hooks.md`.
- C++ header `native/core/abi/kiln_hook.hpp`: `kiln::RawHook` and `kiln::MidHook2`. Use `g.install(...)` on a global. Read `g.caller()` before calling the original, instead of `_ReturnAddress()`.
- Every Kiln service and the core tick now hook through the registry. Only system DLL exports (`LoadLibraryExW`, Vulkan, XInput) and mod hooks outside the game exe still use plain safetyhook.
- `kiln/state/hooks.json` lists every hooked function, its links in order, and other modules' hooks found before or over Kiln. kiln.log says `hooks: <label> chained over <module>+0x...` and `hooks: <module> hooked over Kiln's <label>`.
- EMF mods' `hook`, `hook_pattern` and `hook_address`, and Shroudtopia's `CreateDetour`, are links owned by `emf:<id>` and `shroudtopia:<mod>`. They run newest first, before Kiln's own links.
- ShroudForge's six engine hooks go through kiln.hooks when Kiln hosts it, so another DLL's jump on one of them no longer switches its native runtime off. `KILN_SF_ENGINE_HOOKS=self` keeps the old behaviour.
- `chain.ini` gains `[late]`: entries named there are loaded by kiln-core after Kiln's services, plugins and ShroudForge. `state/native.json` reports them under `chain.late`.
- `compat-rules.json` (Kiln's, then yours in `<configDir>`) can `warn`, load a DLL `late`, or `disable` a DLL, mod or engine. Schemas: `schema/compat-rules.schema.json`, `schema/hooks-state.schema.json`.
- Managed hooks cost less (lab, Wine, `GetComponent`): about 6 ns per call through an empty chain and 59 ns through a managed handler. dev.20 measured about 65 ns and 100 ns.
- Item transfer handlers see `KILN_TRANSFER_DRY_RUN` on a mod's dry-run move. Roll nothing forward there: don't count, log or change anything outside the transfer.
- `component_change` checks an add's payload against the component's size from kiln.types and refuses a mismatch.
- `Overrides` from a background thread belong to the mod that got the handle. Without one they throw `InvalidOperationException`.
- `Texts.Get` returns `null` while `Texts.Preload` is still loading, instead of waiting.
- `Assets.Reflect` returns `null` on builds without kiln.types.
- World program `TryRead`/`TryWrite` no longer allocate or lock per entity. Without kiln.types they log once per program.
- KILN111: items registered with `ItemDefinition` count. A game-style name missing from your local catalog is now info, not a warning.
- Launcher commands: `chain_view`, `chain_set_late`, `library_unused`, `library_users`, `library_remove_many`.

## Breaking and behaviour changes

- A v1 `detour` (and managed `Hooks.Detour`) now passes **every** argument to the original, not only the first four.
- Hook order between Kiln's own services follows the registry (priority, then registration). The core tick links stay innermost.
- EMF and Shroudtopia mod hooks now run before Kiln's own links on the same function.
- Library removal is refused while the game runs, even with force. A running server blocks it only when its profile points into the Library.
- Item transfer handlers are now also called on dry-run moves (not on silent ones), with the dry-run flag set.
- Managed: background-thread override claims without a mod throw. `Texts.Get` can return `null` during a preload. Status lines show the last snapshot and refresh a moment later.
- npcai faction hooks and creatures rules keep their links after 64 on/off rounds, answering nothing, because links are never freed.
- kiln-eml's `files.json` gains change stamps. Older Kiln reads it fine. Use kiln-emf and kiln-eml from the same release: portrait cache codes 5 (busy) and 6 (full) are new.
- An older proxy ignores `[late]` and loads those DLLs early.
- A Nexus-off build deletes the stored personal Nexus API key on start.

## Client checklist

Only a real client or a joined player can confirm these.

- Hooks on the client: Kiln's menu opens and draws, the camera and render hooks work, the in-game UI hooks behave as in dev.20 (ui, render, game; input and Vulkan stay on safetyhook).
- Chat: with kiln-emf's client chat bridge on, Kiln chat commands and EMF mods' chat both work, in both directions.
- Services a-m with a player: item moves and quick stack, combat (fall damage, regen), abilities, audio on the client (voice-over, narration, mod sounds).
- XHL or another DLL that hooks first: ShroudForge still starts. This path is dormant on the current game build (no shipped profile names engine hooks).
- Closed DLL mods: switch "Load after Kiln and ShroudForge" on for XHL-Core. Next start, XHL works, kiln.log shows it loaded late, and the overlaps panel updates.
- Library guard: while Enshrouded starts with an EML mod active, Remove or Clean up of that version is refused. After the game closes, removal works. Clean up never lists a version the active profile points at.
- On a `/home -> /var/home` host, the profile's EML mod loads.
- EML start cost on the real install: the first start reads about 48 GiB once. After that kiln.log shows `hashed` in KiB and `nothing changed` within a second or two. If it says `Change stamps are not trusted here`, note the reason.
- EMF portraits: the game enters the world without waiting when every picture is current, and pictures still show.
- Mods tab status lines refresh without stalls.
- Windows: a PC that had dev.19's Nexus links on over Vortex gets them back (the registry key points at Vortex again). A junction inside the game folder is still refused; one above it works.

## Known limits

- Reordering links that are already installed is not atomic for calls in flight. A call at that moment can skip a link or run one twice. It never crashes.
- Hook links are never freed. A process can create at most 65,536.
- Many new paths were verified only under Wine: unit tests, Wine host tests and dedicated-server labs. Not on Windows, and not in the real client.
- ShroudForge's host hooks are dormant on the current build: no shipped game profile names engine hooks.
- exFAT and FAT game folders refuse CRC reuse, so EML reads every file in full there, as before.
- A compat rule's `disable` cannot stop a native mod whose DLLs load in the `dllmain` phase: the proxy loaded them before the core ran. Only the launcher's chain.ini keeps them out.
