# Kiln 0.2.0-dev.31.18

## Players and server admins

- **Respec with Runes from your linked chests.** With a mod that links chests for you (Streamlined Logistics and others, when they opt in with `Respec`), unlearning a skill node and the Flame Altar's skill reset take their Runes from those chests too, after your bag and your base's Magic chests, all or nothing. Nothing comes from the linked chests when your bag and the Magic chests already cover it, and the free reset the game makes on its own when a skill tree no longer checks out stays free. With a Kiln client the skill tree and the altar count the linked Runes, so the unlearn and the reset are offered; a vanilla client still counts only its bag and the Magic chests. Thanks to Fuzen777 for the request and the careful write-up (kiln#150).
- **ShroudForge mods can change the world's blocks again.** Under Kiln every ShroudForge voxel write was refused ("voxel write was rejected before changing the world"), so mods like Altar Cleanup found the cells and changed none. Kiln now writes ShroudForge's cells itself, on the server world's thread, through the game's own block writer. The mod keeps its undo, and the cells are saved where the game saves them (inside base build zones), as without Kiln. When Kiln still refuses a write, kiln.log says why on a "ShroudForge voxel write ..." line. Thanks to netjunk for the report and the logs.
- **A ShroudForge mod with one failed change no longer shows as not loaded.** When a mod reports that its last change did not apply (`write-failed`) and ShroudForge still runs it, Kiln's in-game mod menu shows it loaded, with the report as a warning. Red is kept for mods that did not load or were stopped. Reported by netjunk.
- **Set a ShroudForge mod's shortcut by pressing it.** In Kiln's menu (Mods > a ShroudForge mod), click the shortcut box and press the key, or the middle or a side mouse button, with Ctrl, Shift or Alt if you like. Kiln saves the code ShroudForge reads for that key on any keyboard layout, so no more `SDL:47`. Click the box again to stop waiting; Backspace, Delete or Unbind leave the mod without a shortcut. The mouse wheel and controller buttons are refused with the reason. Typing still works (`Ctrl+G`, `F5`, `Mouse4`, the key's own character such as `Ü`, or ShroudForge's own `Ctrl+SDL:10`), and a shortcut Kiln cannot read says so in every language. Thanks to netjunk for the report.
- **Typing in Kiln's menu no longer triggers ShroudForge mod shortcuts.** While Kiln's menu, a Kiln text field or the shortcut box has the keyboard, the keys you press there no longer also count as presses for ShroudForge mods. Keys you were already holding are still let go normally. Thanks to netjunk.
- **Key names follow your keyboard layout.** On a German, French or other non-US keyboard, the Keys page and ShroudForge shortcuts show a key as your keyboard labels it (`Ü` instead of `LeftBracket`), and switch when you switch layouts. What is saved does not change. Thanks to netjunk for the suggestion.
- **Update notices clear as soon as you update.** After you install a mod's update yourself (dropping it on the launcher, Add mod, the Library's import), its "Update <version>" notice goes away at once, without restarting the launcher. A notice never names the version you already have, and the next "Check for updates" names the newest version published by then. The same goes for the Catalog's "Update to" on a mod you updated by hand. Thanks to netjunk for the report.
- **Hosting your own world no longer reports your own mods as missing.** Joining a world you host listed your ShroudForge, Flame and other non-Kiln mods as "missing" in kiln.log, although your game ran them. Your own hosted world now never lists anything as missing, and the launcher's Play page no longer offers a modpack for it. On someone else's server, the missing list now also checks the ShroudForge, Flame, Green Eye and SET mods in your game folder, not only Kiln and native mods; a mod you switched off still counts as missing, because the server needs it running. EML mods, EMF's DLL mods and Shroudtopia mods that Kiln runs from your Library are not checked yet, so they can still show as missing. Thanks to netjunk for the report.
- **Play now leaves a server's World and Players tabs.** On a server's page, clicking Play in the launcher's main menu opened the Players tab from the World tab and did nothing on the Players tab. Every main menu entry now goes to its own page from every server tab. Thanks to netjunk for the report.
- **Unsaved changes on a server's page ask before you leave.** Leaving a server's Settings with unsaved changes, or a stopped server's config file you edited, asks first: Save and leave, Discard changes, or Stay (only Discard and Stay when it cannot be saved right now). This covers the main menu, the server's tabs and switcher, and Back, and also a mod's config file edited elsewhere in the launcher. Suggested by netjunk.
- **Clearer support reports.** When kiln-eml handed your EML packs to Kiln's ShroudForge, the report now says so as information ("kiln-eml handed your 8 EML packs to Kiln's ShroudForge at the last start") instead of a problem about EML's own loader. A start that ended while Kiln was still starting no longer reads "did not load Kiln" with dinput8.dll advice; the report says Kiln loaded and at which step the start ended.
- kiln.log and the launcher name mods in ShroudForge's mods folder as Windows does (`C:\...\mods\<mod>`), not `//?/C:/.../mods\<mod>`.
- **The Conflicts page names the EML mod on the field it changed.** An EML mod that changed a value before Kiln is named on that exact field (recipes and loot by their element), also when another mod loads it first or copies the data back afterwards. Registry mods' edits still win. `registry.json` also says who published the game data the registry reads (kiln-eml, hosted or installed ShroudForge, or another loader).
- **Changes made after the world loaded show up.** Another mod's code, an EMF DLL mod or a write outside Kiln now reaches the Conflicts page and `registry.json` within seconds, named by mod and Kiln field, without a reload. The check spreads its reads over several ticks, so big registry packs cause no hitch.
- **Safer mod reloads.** A reload whose new version changes a mod's `side` is refused until a restart, and the running version stays (before, Kiln clients could be refused at the join until a restart). A reloaded mod's data packs keep their place, so the same pack wins a shared field as at the start. The reload reply says when a data pack threw and was set apart.
- **Old registry plans are cleaned up** at the end of each successful start: the plans a rollback or the last good start still needs stay, and so do the newest 10 others.

## Modders

- Mod API 0.2.25. The public additions are #150's: `CraftSourceOptions.Respec` (get/init, off by default: the link also pays the skill respec's Runes) and `const Crafting.RespecSourcesCapability` = `crafting.respec_sources` (Kiln.Blocks); TestKit `FakeCraftSourceRegistration.Respec` and `HarnessCrafting.RespecStock(player)`. Native: `KILN_CRAFT_SOURCE_RESPEC` (8), `KILN_CRAFT_SOURCE_STOCK_RESPEC` (16), `KILN_STATIONS_MAX_RESPEC_STOCK`, and `kiln.stations.set_respec_stock` appended after `fill_flags` (table 328 bytes). Wire: message 11 on `kiln:craftstock` (`required: false`), the server's respec snapshot; older peers drop it.
- ShroudForge fork `kiln-dev31-voxel-write` (`6cf01443`, on top of `a9dc2ad2`): the host table (`abi/runtime_host.h`) gets two optional members, `voxel_write_ready` and `voxel_write`. With both, `runtime.world.voxel.write` and `runtime.has("runtime.world.voxel.write")` go to Kiln, which keeps ShroudForge's outcome codes (0 written, 1 refused before any change, 2 put back, 3 uncertain) and its limit of 65,536 cells a call. Like ShroudForge's own writer, Kiln refuses a box outside the voxel grid, a write that would reach another world than the one the mod asked in, and, after an uncertain write, every further voxel write in that world until it is loaded again; kiln.log names each reason. A host without the members, and ShroudForge's own loader, keep upstream's writer.
- kiln.build: native `KILN_BUILD_F_GAME_SAVE` (bit 6) writes under the game's own save rule (no Kiln save region, no save-region hook needed); refused together with `KILN_BUILD_F_TRANSIENT`. It is not in the managed `BuildFlags`.
- Kiln's in-game mod menu shows a ShroudForge mod's `write-failed` effect as loaded with a warning while ShroudForge lists the mod active; the `error` effect and ShroudForge's per-mod errors stay failed.
- A ShroudForge `keybind` setting still stores ShroudForge's canonical text (`Ctrl+Alt+Shift+Meta+SDL:<scancode>` / `Mouse:<button>`); the in-game page converts readable input before it saves. `keybinds.json` keeps Kiln's stored key names; only the shown names follow the layout.
- Registry and formats: kiln-eml writes a format-2 change journal of EML's own pass (member paths, up to 16,384 per resource) and `eml.json` gains `generation`; archive-writer rows in `registry.json` say `named` `entry` or `field`; `base.writer` names the archive writer that patched the base and `base.archive` what that rests on. Live refusals name Kiln fields (an item's perk slots included), never game members. A Content change made by code (`Content.Apply`, BigStacks) still wins over a registry edit and computes on the game's value; `registry.json` now says so with the value the code set (to stack on the registry's value, make it a registry edit). A mana or stamina cost changed through kiln.gamedata is named by mod and Kiln field.
- Reloads: `RestartRequired: ` for a new version that changes `side`; the reload reply's `data.packs` (with `setApart`, the hook for tools such as Web Admin) is known only after the packs applied again. Re-applying large packs no longer costs quadratic time on the world thread.
- kilnctl's registry proof keeps every loot id across a game update (before, it retired all of them and refused to verify the new build), and its producer samples `items.levels.min` again.
- `kiln/state/last-server.json` gains `hosted` (true for this game's own hosted world, with `missing` empty; an older file leaves it out and the launcher compares the server id). In other answers `missing` covers other engines' mods in the game's engine folders too, compared by the hash the server advertises; a copy that is switched off counts as missing.
- Report: kiln-eml's `aside` reason from Kiln's ShroudForge plugin speaks for the start its `eml.json` pid names; a file from another start gets the Info finding `eml-under-shroudforge` instead of the `own-loader` problem. After a launcher start with no fresh boot.json, a `kiln/state/progress.json` of that start that is not `ready`, `idle` or `failed` makes `not-loaded` say Kiln loaded and the step the start ended in.
- Launcher: the router is a data router (`createHashRouter`), and pages register unsaved work with `useLeaveGuard(dirty, { what, save?, discard })` (`launcher/src/shell/leaveGuard.tsx`).
