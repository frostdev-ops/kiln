# Kiln 0.2.0-dev.31.next: game input for client mods (hold-to-repeat, a bow that lets go when drawn)

Kiln provides the framework for attack and action input mods: a client mod can read the local player's game actions
after the game has resolved them, and press or release an action for one input step. The first user is Combat And
Attack Tweaks (its Hold To Light Attack). Players see nothing new without a mod that uses it.

## Players and server admins

- **Hold-to-repeat and auto-release mods get a safe base.** A mod such as Combat And Attack Tweaks can turn a held
  attack into repeated light attacks, or let a fully drawn bow shoot by itself, through Kiln instead of its own hooks
  into the game. Your key bindings and controller work as you set them, and nothing happens while a game menu, the
  inventory, the map, the chat, Kiln's menu or a Kiln window is open, or while the game is not the window in front.
- **Nothing changes by itself.** Kiln does not repeat, press or release anything on its own; only a mod you install
  does, and only on your own character.
- **Multiplayer:** the presses are your own input and go to the host or server like the rest of it; the host or server
  still decides what happens. Each player's hold-to-repeat setting is their own, and a host or server needs no setup
  for it. A dedicated server does not use it at all.
- **Thanks** to the Combat And Attack Tweaks author for the detailed notes on the game's input writer and input message,
  which this is built on.

## Modders

- **New in mod API 0.2.28: `Kiln.GameInput`** (assembly Kiln.Client, which now references Kiln.Combat for
  `Kiln.ActionKind`): `Available`, `IsHeld(GameAction)`, `WasPressed(GameAction)`, `OnSample(GameInputHandler)` and
  `Repeat(GameAction, TimeSpan interval, Func<bool>? whileHeld = null)`; `GameAction` (`PrimaryAttack`,
  `SecondaryAttack`, `Block`, `Dodge`, `Jump`, `Interact`; append only); `GameInputSample` (a ref struct: `Player`,
  `HeldKind`, `BowFullyDrawn`, `IsHeld`, `Press`, `Release`) and the `GameInputHandler` delegate. The same surface as the
  preview SDK 0.2.0-dev.31.30-preview.1. Since Kiln 0.2.0-dev.31.30 (mod API 0.2.28).
- **Where it reads and writes.** In the game client's own input writer, once per client world step on the main thread,
  after the game's bindings, controller mapping and menu handling, before the simulation and the input message use
  the record. No keyboard polling. Each `GameAction` is a set of the game's `PlayerInputType` bits; `Press` clears the
  action's derived bits (tap, hold, release) and sets its "down" bits, so a one-step press is a tap and never the heavy
  attack.
- **Gates:** handlers and repeats run only with the in-game HUD up (no other game screen, the chat included), without
  Kiln's menu or a capturing Kiln window, and with the game window in front (kiln.ui's screen and status and the
  foreground window, read each client step). Reading is never gated.
- **Stale presses** are Kiln's: when the game skips its writer for a step, Kiln clears the bits it pressed before the
  input message would send them again (same record, player, session and digital word, a later step). Always on.
- **`Repeat`**: a press for one step, releases until the interval (at least 50 ms), again, while `whileHeld` (default:
  the action itself is held). It ends when disposed, when its world ends (the world of its first sample) or when the
  mod unloads. **`HeldKind`** comes from Kiln's item catalog and the game's ranged weapon state; **`BowFullyDrawn`** is
  the game's own draw test, with skills and `ActionSpeed` included.
- **Errors:** `OnSample` and `Repeat` throw `InvalidOperationException` on a dedicated server, where the capability row
  `client.game_input` is off, outside mod code or with 64 subscriptions already; reads never throw (false).
- **Native:** `kiln.client.game_input` v1 (`kiln_client_game_input.h`: `last`, `subscribe`, `repeat`, `unsubscribe`),
  new sigdb feature `client.game_input_sites` on client 26430625 (with `client.input_observation`), and kiln.log says
  once when it does not resolve. Nothing is hooked until the first use; then two mid links (kiln.client's observation of
  the input writer, now shared with building input, and the guard in the input message).
- Guide: docs/kiln/modding/game-input.md (hold-to-repeat in about ten lines); reference:
  docs/kiln/services/client-game-input.md; the game side: docs/re/game-input.md; for the Combat And Attack Tweaks
  author: docs/kiln/modding/catt-porting-input.md (sites 19 and 20 and the user32 polling).
- Tests: host tests of the rules (`test-client-game-input.sh`, ASan/UBSan and TSan: bits, gates, repeat timing, the
  guard, threads), the capability row (`test-caps.sh`), a read-only test of the game's code
  (`tools/sigport/tests/test_client_game_input.py`), and C# tests over a stand-in table (`GameInputTests`).

## Not yet seen in a real game

- Nobody has held an attack or drawn a bow with this build yet. It rests on static analysis of client 26430625, host
  tests and C# tests.
- On a joined client, `BowFullyDrawn` compares the host's replicated draw start with the client world's clock (as
  Combat And Attack Tweaks does today); that they line up was not watched.
- Which press pattern the game turns into a light attack is the Combat And Attack Tweaks author's (the old Hold To
  Light Attack mod's); Kiln did not trace the server side of it.
