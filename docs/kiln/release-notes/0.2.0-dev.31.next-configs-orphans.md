# Kiln 0.2.0-dev.31.30 (the configs-orphans lane's notes)

Mods, More, Configs no longer lists the settings of mods you removed as if they were live. They sit apart, read-only,
under "Not installed", and you can clear them.

## Players and server admins

- **A removed mod's settings are marked "Not installed".** Remove keeps a mod's settings on purpose, so that adding the
  mod again brings them back (the box "Remove its settings too" in the Remove dialog is off unless you check it). Those
  kept config files were listed in Mods, More, Configs next to the files of the mods you have, with switches that looked
  live, so it looked as if Remove had removed nothing. The window now puts them under "Not installed: kept for when you
  add it back", after the files of your installed mods. Their switches, fields and raw file are read-only, with a line
  saying that changes do nothing until the mod is back. A mod you only switched off is installed, and its file is as it
  was.
- **Clear settings.** Each of those files has a Clear (the small bin on its row, or "Clear settings" in its card), and the
  group has "Clear all". Kiln asks first and names the files. Then it moves them, with their schema files, into the
  settings backups that "Remove its settings too" already uses (`backups/mod-settings/config-<profile>-<time>/` in
  Kiln's data folder, laid out as the files were, with a `removed.json` that says where each came from, so you can put
  one back by hand), and a message says where the copy is. If you add the mod again later, it starts from its defaults.
- **Your installed mods' settings are never touched.** Kiln checks again when you press Clear, not only when the window
  listed the files: if the mod came back meanwhile, or a file is not an orphan for any other reason, or Enshrouded is
  running, the whole request is refused and nothing is moved.
- **How Kiln decides.** A file is "Not installed" only when its mod is nowhere Kiln can see one: not in the profile (on or
  off), not in the Library, not in the folder of a game Kiln knows (a mod you put there yourself, or a folder Kiln kept
  at the last start). When Kiln cannot tell whose a file is, or cannot read one of those places, it marks nothing. Kiln's
  own files (`native.json`, `keybinds.json`, ...) and Shroudtopia's shared `shroudtopia.json` are never marked. The
  Configs page of a server is not marked either: a server's mods are not the profile's.
- **Thanks** to HTR for the report (Discord #general): "does Remove really remove?" Remove does remove the mod; its
  settings stay on purpose, and now the window says so and lets you clear them.

## Modders

- No mod API change: mod API 0.2.26, as in 0.2.0-dev.31.29. Nothing to change in a mod: the config files a mod writes
  (`<id>.json` with its `.schema/` snapshot, EMF's `emf/<id>.ini`) are read as before.
- **Launcher contract.** `config_list` gives each file an `orphaned` flag (true only for a profile's file whose mod is
  installed nowhere); `config_clear_orphans(target, files)` is new, a profile's only. Kiln-manage has
  `config_orphans::{list_profile, owner_of, mark, Installed}` and `mod_settings::clear_orphans`. docs/kiln/launcher/
  contracts.md and app.md (Configs) have the rules.
- **Whose file it is.** The mod of a config file is the schema snapshot's `mod` (what `Config.Register` writes; kiln-emf
  writes one for EMF), else the file name in `<kind>/<id>.<ext>` of an engine's kind (EMF, EML, XHL, ShroudForge, SET,
  Greeneye, Flame, ...). Ids are compared without case. A config the core registers outside a mod names the mod
  `kiln`, and the core's files (`native.json`, `keybinds.json`, `rules.json`, `menus-client.json`, ...) are never a
  mod's. A file with no snapshot outside an engine's folder has no owner, so it is never marked or cleared.
- **The backups.** Clear writes `config-<profile>-<time>/` in `<data>/backups/mod-settings/` with `profiles/<pid>/config/...`
  and `removed.json` (`{format, kind: "config", id: <profile>, removed, mods: [ids], items: [{from, backup}]}`), the layout
  and record Remove's settings removal writes, so one reader handles both.
- Tests: kiln-manage unit tests (the owner of a file per mod kind, Kiln's own files, nothing marked while a place is
  unreadable) and `tests/config_orphans.rs` (every kind marked when nothing is installed; installed on or off, in the
  Library and in a game folder not marked; an unreadable profile marks nothing; Clear moves the files and their
  snapshots into the backups; Clear refuses an installed mod's file, Kiln's own, an unknown one, names outside the
  folder, a running game and a mod that came back, changing nothing). The launcher's log line, the front-end's groups and
  read-only controls (`unit/config-orphans.test.tsx`) and a Playwright spec on the mock (`tests/config-orphans.spec.ts`).

## Not yet seen in a real game

- Nobody has opened Configs on a real profile with removed mods, or pressed Clear, with this build yet. It is tested on
  temp folders and on the launcher's browser mock; the launcher's own window (Tauri) was not run.
- The "Not installed" test looks at the profile, the Library and the game folder Kiln knows. A mod that something other
  than Kiln put somewhere Kiln does not look is not seen; its file would be marked. Clear always keeps a copy in the
  backups.
- The new texts are in all eleven launcher languages; the ten translations are machine translations that no native
  speaker has read yet.
