# Kiln 0.2.0-dev.27

NoClip as a rule of its own, asked for on GitHub (issue 25), and the calls mods were missing: take a buff off, see where a player looks, kick and ban, hear only the hits you care about, put an item on a player, choose the weather, show a value of one item in players' games, roll affixes onto an item. EMF mods built for EMF 0.6.3 and later start again. All of it works on a test server with no player; what a player's own game shows waits for the guided client pass, which has a check for each.

## Mod authors

- **The mod API is 0.2.2.** Everything new is additive: no public member of 0.2.0-dev.26 was removed or changed.
- One call shape no longer compiles: `Events.On<T>(handler, default)`. The second argument can now be a priority or a filter, so the compiler cannot choose; write `EventPriority.Normal` (or leave it out). A built mod is not affected.

### NoClip
- `PlayerRules.NoClip` is a new rule: the player's character flies through terrain, building blocks and props. It flies as in character flight (jump climbs, sneak sinks, sprint is faster), takes off at once, also from the ground and from water, and never lands. It is separate from creative mode and from character flight, and it grants nothing else: no invulnerability.
- `NoClip.Set(player, on)` is Kiln's own switch for a player and returns a result with `Ok`, `On`, a `Reason` and a message; `NoClip.Of(player)` says how it stands (`On`, `Active`, `LastFree`, `Restoring`); `NoClip.Available` and the capability `rules.noclip` say whether the running game build can do it. A rule set of your own can carry `NoClip = true` as well.
- A death or a teleport of the player ends it, and it has to be asked for again: `NoClip.Set(player, true)`, or `Update` on your rule set. `PlayerNoClipEndedEvent` says why it ended (`RuleEnded`, `Death`, `Teleport`).
- When NoClip ends while the character is inside something, Kiln first moves the character back to the last place where it was in open space and only then lets collision return; the event's `RestoredTo` says where. A move that fails is tried again, and until the character is in open space it keeps flying without collision (`NoClipState.Restoring`). The game itself does not push a character out of solid ground: on a test server one whose rule ended inside rock fell through the world.
- `RuleSet.Update` now counts at once: `Rules.Of(player)` can be read right after it, as after `Rules.Apply`. Before, the change took effect at the next server step.

### Buffs
- `Abilities.RemoveBuff(target, buff)` takes a buff off a player, a creature or an NPC through the game's own removeBuff, by the buff's GUID or its id (`GameBuffs.Ids`). The result is the game's answer: `Ok` is false, with a reason, when the entity did not have the buff. `BuffRemovedEvent` follows a removal.
- `Abilities.BuffsOf(entity)` lists the buffs on any entity (`EntityBuff`: id, slot, time left, level). The game keeps buffs on the server: a joined client gets an empty list.
- The capability `abilities.buffs` is pending while no server world runs (a client in its menu) and available once one does; `abilities.buff_list` says whether the list can be read.

### Players
- `PlayerStates.AimOf(player)` says where a player's camera is and where it looks (`PlayerAim`: `Origin`, `Direction`, `At(metres)`), read on the server from what the player's game sends. The camera is behind the character: a ray for "what is the player looking at" starts at the camera.
- `Players.Kick(player, reason)` and `Network.Kick(peer, reason)` refuse a connection with a reason; a player with Kiln reads the reason, one without gets the game's own "could not join" message. `PlayerKickedEvent` follows.
- `Bans` is Kiln's own ban list (`Add`, `Remove`, `Find`, `All`; by player or Steam id, with an optional duration), kept in the server's Kiln data and enforced whenever a connection names its account. `PlayerBannedEvent` and `PlayerUnbannedEvent` report changes.
- `PlayerLoginEvent` is posted once for each connection when it first names its player. Cancel it, with a `Reason`, to refuse the player (a whitelist is three lines).

### Events
- `Events.On<T>(handler, EventFilter.ForEntity(entity))` delivers only the events about that entity (or `ForEntities`). It works for every event that names its entities (`IEntityEvent`: the combat events do).
- For hits it also saves work: Kiln holds a hit for mods only when a handler could want it. A mod that watches one training dummy no longer has every hit in the world held for it. A handler without a filter gets every hit, as before.

### Data on one item
- `InstanceData.Claim(parked, item)` puts a value that Kiln had set aside onto an item you name; `InstanceData.Discard(parked)` drops it. Both may be called from a handler of the item data events.
- `InstanceData` values can reach players' games. Give a key `Sync = InstanceSync.Holder` (the player who holds the item) or `Nearby`, declare the same key in the mod's client side, and read it there with `InstanceData.Synced` or `InstanceDataSyncedEvent`. A value never goes to a player the key does not name.
- What is sent is acknowledged: an update lost on the network is made good within about a second, or within ten seconds when nothing follows it. A game is sent at most 256 KiB a second and never more than the 4,096 items it keeps, its own first. A game that keeps reporting losses is started over less and less often (up to a minute apart), so a player's game cannot make the server send more by claiming them.

### Items
- `Items.Equip(player, from, slot)` puts an item from the player's backpack on, in the slot you name or the item's own; `Items.Unequip(player, slot)` takes one off into a free backpack slot. Both run the game's own equip on the server, with all its checks. The result (`EquipResult`) says what moved where, or why not; `EquipOptions.DryRun` asks without changing anything; `EquipChangedEvent` follows each change Kiln made. Capability `items.equip`.
- A mod item with a model of its own now lies on the ground as that model. Before, it took the ground model of the item it was made like, also when that looked nothing like it. `Dropped` names another model. Items written for earlier releases change their look on the ground with this release unless they set `Dropped`.

### Affixes
- Bonuses rolled onto one item: define affix kinds and pools as blocks (`Blocks.Define`, or the `affixes` and `affixPools` sections of `blocks/*.json`; `Affixes.Define`, `DefinePool` and `Affixes.Load` are the same registration), roll them onto an item, and Kiln applies them while the item is in hand or worn. All 39 stats of the game work. [affixes.md](../modding/affixes.md) has the whole of it, the sample `AffixSword` a sword with one of three.
- An affix or an affix pool cannot share its name with a block of another kind in its mod; such a definition is refused with a `BlockError`. The same name and the same kind defined again replaces the earlier one, and after `OnLoad` a data file's definition is the mod's.
- A section of a `blocks/*.json` file that is not an object (a list where the blocks should be) is that file's error naming the section; the file's other sections and the mod's other files still load. Before, it stopped the reading of the mod's block files.
- A pool that can never reach its minimum is refused when it is defined, and a roll that cannot reach it is refused with a reason. A rolled item keeps the stat it shows when its affix is defined anew.
- Not yet: flat damage on a hit, a share of a pool, lines in the game's own tooltip, rolls by themselves on a drop or a craft.

### World
- `World.Write`, `World.Update`, `World.WriteField` and `World.WriteAt` change a component of an entity through the game's own write tracking: the change is saved with the world and is still there after a restart. List the component types your mod writes under `"writes"` in kiln.mod.json (Kiln.Sdk adds the types your code writes). The write runs in the next sim step, and the result says what became of it. Capability `world.tracked_writes`; `ComponentWrittenEvent` follows a change.
- A tracked write goes to the entity its id named at the call, never to another entity that got the id since (the next player in a slot). For an entity without a spawn time it is not kept waiting behind a full step: it answers `Dropped` and the mod asks again the next step. 512 writes run per step; all mods together share 91 component types.
- `World.TryWrite` still works and is obsolete: it is `World.WriteRaw` now, a raw store the game neither saves nor sends, for inputs the game reads in the coming step.
- `World.Query` gives entity sets, and world programs take the generated component types (`TryGet`, `TrySet`, `TryGetOther`, `TrySetOther`).
- Kiln.TestKit has a fake world (`kiln.Entities`): this world code runs under `dotnet test`, and the fake's limits are tested against the native service's.

### Weather
- `Time.SetWeather("rain", TimeSpan.FromMinutes(10))` starts a weather phenomenon by its name, on every weather layer that has one of that name or on one layer; without a duration it is held until `Time.ReleaseWeather()`. `"none"` is a clear sky. The game itself runs the change, with its fades, and tells every player's game.
- `Time.Weather` lists the layers (what runs, what Kiln holds, when the game rolls next), `Time.WeatherPhenomena` the names, and `WeatherChangedEvent` reports every change, the game's own rolls too (`ByKiln` tells them apart). Capability `time.weather_choose`.

### Definitions baked at build
- Kiln.Sdk now writes the quests (with their NPCs and dialogues), `GameTree.Define` nodes, VFX and materials that a mod defines in code into the mod when it is built. They are there at the first start, on the server and in every player's game. Before, the first start after an install did not have them. `KilnBake=false` turns it off; [baked.md](../modding/baked.md) says what is baked and what is not.

### Cooked files
- Each cook Kiln runs records what it wrote, in the game's `kiln/state/cook-receipts`. A cooked file that no receipt of the game lists was not made there: it was shipped inside a mod, copied in or changed afterwards. By default (`"cooked": "warn"` in `kiln.json`) such a file still loads, and kiln.log names it and says how to cook it. A later release will refuse such files; `"cooked": "local"` does so now, and `"any"` asks nothing (for a development server).
- So ship recipes and sources, never `assets/cooked`. `kiln cook --force` cooks every recipe again.
- A mod's assets are read from its own folder only: a link that leads out of it, or to another mod's cooked file, is an error.
- What the rule is for: it keeps shipped, copied or altered cooked files (content that a mod's identity does not cover) from loading as part of a mod. It is not a barrier against code that already runs under the player's account.

### One contract in every service
- Every service now answers the same way ([contract.md](../modding/contract.md)). A call whose capability is off throws `KilnUnavailableException` naming the row. It is still a `NotSupportedException`, so an existing `catch` keeps working; the message starts with "<row> is not available:".
- Capability rows are there from the first tick and say what the call will do: session rows are pending until a server world runs, and a service whose native part is missing lowers its features (`rules.*`, `world.*`, `saves.*`, `net.*`, the players' rows, `time.speed`, `combat.attributes` and the others) and takes that back when the part appears later (it is looked for again about once a second).
- Results are kiln results (`IKilnResult` with `Ok` and `Reason`): `HitResult`, `CastResult`, `FuelResult`, `QuestResult`, `ConversationResult`, `ProgressionResult`, `CreativeResult`, `SaveResult`, `TeleportResult`. New members `SaveResult.Ok` and `TeleportResult.Ok`.
- A change Kiln makes has an event. New: `CombatChangedEvent` (also for god mode ending when its mod unloads, and for `Abilities.Attributes.Add`), `TimeSpeedChangedEvent`, `ImpactVariableChangedEvent`, `PlayerProgressionChangedEvent`. A change made inside the handler of its own event arrives first thing in the next step instead of looping. It is never dropped for room; a newer write of the same value takes its place, and it is dropped when the entity or the player it names is gone. `PlayerProgressionChangedEvent` says only what the request itself changed, not what the game changed in the same steps.
- Entry points that take a person or a living thing, under names of their own: `Spawn.DestroyIfAlive`, `Chat.TellIfOnline`, `Permissions.PersonHas`, `PermissionSubject.ForPerson`, `Players.FindPerson(PlayerRef)`.
- Members carry what they need: `[RequiresCapability]`, `[ServerOnly]`, `[TickThreadOnly]`, `[AnyThread]`. The analyzers read them.

### Analyzers
- New warning **KILN120**: a Kiln result (`IKilnResult`, for example from `Items.Equip` or `NoClip.Set`) that nobody reads. Check `result.Ok`, or write `_ = ...` to drop it on purpose; the code fix offers both.
- New warning **KILN121**: a member marked `[RequiresCapability("row")]` used with nothing asking `Capabilities.Is("row")` (or the service's own guard property) first and no `catch` of `KilnUnavailableException`. A helper of your own that does the check is not followed: catch at the command, or mark the caller `[RequiresCapability]`. Either rule is switched off with `dotnet_diagnostic.KILN121.severity = none`. [analyzers.md](../modding/analyzers.md) has what each rule sees and does not see.
- A project that names its features in `<KilnFeatures>` instead of a kiln.mod.json has them counted as asked.

### Tests without the game
- Kiln.TestKit fakes spawning, chat, items, combat and time: your mod's own calls run under `dotnet test`, and the test reads what the mod did (`kiln.Spawned`, `player.Chat`, `player.Say`, `player.Inventory`, `kiln.Combat.Hit`, `kiln.Time`). The fakes answer as the native services do, also for a refusal and for a mod that unloads with work queued.
- Quests and talent trees your mod defines run in unit tests on fake players. What the kit does not model (weather, equip, item moves between inventories, the game's journal and skill tree) says offline instead of pretending. [unit-tests.md](../modding/unit-tests.md) lists it.
- A test that registered a command no longer needs `AllowUnavailable = ["kiln.chat"]`.

### Samples and templates
- New samples, each for one topic and each holding to the contract (the capability asked first, a refusal read and passed on): `SavedData` (world, player and entity data), `AdminTools` (strikes, kick, ban, NoClip for an admin), `CalmBell` (an interaction offer and a game setting changed for a while), `QuietServer` (pacing an empty server), `Loadouts` (`Items.Equip` and `Items.Unequip`), `SkyControl` (the weather), `AffixSword`, `ItemData`, and for the advanced tier `EngineRoom` (the game's systems listed, profiled and hooked; one field of a game resource changed as a claim).
- New `dotnet new` templates, one topic each: `kiln-events`, `kiln-saved-data`, `kiln-rules`, `kiln-network`, `kiln-screen-effect`, and for the advanced tier `kiln-hooks`, `kiln-shader` and `kiln-world-program` (a program of your own in the game's scheduler).

### EMF mods
- kiln-emf serves EmfApi v40 (EMF 0.6.8). `chat_tell_ex`, `chat_broadcast_ex` and `world_to_screen` work. The other functions EMF added since 0.6.0 answer "not available" for now, as EMF does on a game build it does not know: player events, item names, character names, hits and hit rules, buffs, markers, map actions, canvases, `remove_building`, paths, doors, enemy orders and move orders. [emf-parity.md](../emf-parity.md) has each answer.
- A mod that is being cooked is no longer replaced or removed when you change its version or switch it off in a profile: Kiln asks you to wait until the cook has ended. Pressing Play again right after a start no longer cooks the mods while Steam starts the game.

## Players

- **`/noclip`** (admins): fly through the ground and walls. `/noclip` switches it for yourself, `/noclip on|off <player>` for someone else, `/noclip status` says whether it works here. Your game needs this release too. It ends when you die or teleport; when you turn it off inside something, you are put back at the last place where you were free.
- **EMF mods made for EMF 0.6.3 to 0.6.8 start on Kiln again**, EMF's Lua mods among them (Beastmaster, Necromancer, Bounty Board and the others). Since EMF 0.6.3 they stayed off unless EMF itself was installed.
- A Kiln game now answers an EMF server's mod check, so a server that refuses games without its mods no longer kicks a Kiln player after a minute. When your game lacks a mod the server needs, one note tells you which.
- **When ShroudForge's own loader runs next to Kiln and cannot write its mods into the game data, the launcher says so**: on the Steam Deck's Home, in the desktop's engine list and in the support report. It names the mods that did not load and what to change. This happens with ShroudForge 1.7.9 on Linux and the Steam Deck while the launch options still have `dbghelp=n,b` and `winmm=n,b`; take those two out and Kiln's own ShroudForge runs the mods.
- Mods can give single items their own rolled bonuses and show you values that belong to one item. Nothing changes when you play without such a mod.
- **The save editor works on the Steam Deck**: a new Editor tab you use with the controller alone, with a number pad for amounts and levels. Not on the Deck yet: "Open a save file…".
- Your changes in the save editor stay when you leave the page, and the editor asks before it drops them: for another character, and for Discard. (The desktop window can still be closed with unsaved editor changes without a question.)
- The save editor no longer overwrites a save the game wrote after you opened it: it offers "Read again". When you have changed nothing, it reads the save again by itself after you played.
- A save with items from a mod that is gone opens read-only in the editor, and the backups list says which backups are the game's and which are Kiln's.
- **The launcher cooks the mods that need it.** A mod with a cook recipe (models, animations or sounds made from your own game's files) is cooked when you press Play: the launcher says "Cooking" with the mod's name, shows the cook tool's lines and starts the game after. Cook again in a mod's menu repeats it (Y on a mod in the Steam Deck's Mods screen). A cook tool that hangs or never stops printing is stopped, Cancel stops it, and a mod that could not be cooked keeps running on the files it has.
- **Mods with a cook recipe no longer need the Kiln source.** `kiln` and the launcher carry the cook tools and unpack them on first use. On Windows the launcher brings its own Python (python.org's embeddable 3.14, in the launcher's own folder: nothing is installed and a Python you have is not touched). On Linux the system's `python3` is used (3.10 or newer; one older than 3.14 reads the game's archives through the system's zstd library). When something is missing, the message says what to install.

## Server operators

- **NoClip is off until you allow it.** Set `"allowNoClip": true` in `kiln/config/rules.json` (edits apply within a second). `/noclip` needs the Admin level or the permission node `kiln.command.noclip`. A player whose game has no Kiln, or an older Kiln, never gets it.
- **`/kick <player> [reason]`, `/ban <player|steamid> [30m|12h|7d] [reason]`, `/unban <id>`, `/bans`** are Kiln's own commands (Admin level, or the nodes `kiln.command.kick`, `.ban`, `.unban`, `.bans`). The ban list is `kiln/data/kiln-players/bans.json`, apart from the game's own list. A ban that cannot be written to disk is refused instead of holding until the next restart.
- `/instances claim <record> <holder> <slot>` and `/instances discard <record>` put a set-aside item value on an item or drop it, for every mod.
- A mod whose `"writes"` list Kiln cannot read still loads, with a warning; only its tracked writes are refused. A server whose mods list no `"writes"` gets no extra program.
- A Kiln server answers an EMF game's mod list with its own and logs the difference (`EMF mods check: player ...`). It does not refuse joins.
- The greeting line to games without EMF or Kiln follows EMF 0.6.8: 10 s after a player connects and once more 35 s later (before: up to four times).
- **Cooked mods after the update:** you do not have to do anything, files cooked by an older Kiln keep loading, with a warning in kiln.log. Run `kiln cook <server folder>/kiln/mods/<mod> --game <server folder>` once for each mod with a recipe: it writes the missing receipts and the warnings go. A later release will refuse cooked files without a receipt.
- `kiln cook <server folder>/kiln/mods/<mod> --game <server folder>` works with the `kiln` from a release's `sdk/` folder alone: `KILN_REPO` is no longer needed (a checkout still wins when it is set). It needs Python 3.10 or newer on the machine.
- Kiln.Gameplay and Kiln.Combat no longer start their game-event listeners on a server whose mods never use them, so a mod that listens to every event cannot delay or cancel hits and crafting there.
- Kiln's sample mods answer "not on this server" instead of failing when a feature is off on that game build.

## Fixed

- The launcher's save editor stopped an item's amount at the game's stack size, also when a mod raises stack sizes (GitHub issue 23). An item that stacks now takes any amount up to 65,535, which is what the save holds, with a note when it is above the game's stack size.
- A mod whose kiln.mod.json holds a string that is not text (half of a surrogate pair written as an escape) stopped the scan of all mods at the start. It is that mod's error now, and the others load.
- The game's main menu had no MODS entry in any start in which Kiln ran ShroudForge (a ShroudForge mod on in the profile). ShroudForge changes two calls in the main menu before Kiln looks for its own place there, and Kiln did not recognise that change. The entry is back, with Kiln's ShroudForge and with "Use my installed ShroudForge". The Mods entry of the pause menu was not affected.
- The support report called it a problem, and named "EML's own loader", when kiln-eml had stood aside for the ShroudForge that Kiln runs, which is how the two work together. It is a note now, and a warning that names the mods when ShroudForge has some of the profile's EML mods switched off or not in its folder.
- The launcher's log has a line for each changed setting (for Kiln's own settings with the new value, for a mod's settings with the name of the setting only), so a support report shows when a switch was changed.
- Saving in the save editor made two backups of the save; it makes one.
- Typing in the save editor's "Add item" search stuttered; the letters now appear as you type (the list itself appears no faster than before).
- In Deck mode, L1 and R1 pressed quickly in a row skipped presses; every press counts now.
- In Deck mode, several errors at once could make the bar of messages stop working on a slow machine (the messages measured themselves again and again). Each message is measured once.
- A quest whose completion a mod cancelled (`QuestCompletedEvent`) ran the last step's "when done" actions anyway, and ran them again at every retry: a reward could be given more than once. The completion is asked for first now, and the actions run once, when it goes through. (0.2.0-dev.26 had this too.)
- An asset manifest whose patch offset was a negative number made Kiln write a few bytes in front of the resource it was patching, in the game's memory (0.2.0-dev.26 had this too). The offset is refused now.
- The Deck (the launcher's gamepad view) showed a long error as a line that ran off the screen. A long error now opens as a dialog, also when the long text is its title, and stays until it is read.
- Two launchers open on the same data folder could drop each other's "do not show again" notices.
- A release build now uses one fixed Rust version for everything it builds (the release of 0.2.0-dev.26 stopped halfway when the toolchain moved under it).
- The check of the material cook rules read a game archive that a texture mod had patched and reported the game's own materials as broken; it reads the game's unpatched archive.

## Known limits

- **Nothing of NoClip has run in a real game.** On a test server a test character with the rule took off from the ground, sank 6 m into solid rock, came back up through the surface, was put back at its last free position when the rule ended inside the rock, and lost the rule on a teleport and on death. What the player's own game shows (the same movement in its prediction, the camera inside terrain, what other players see) waits for the guided client pass: hosted single-player under Proton first, then a dedicated server.
- NoClip judges open space from terrain and building blocks. Inside a prop (a rock, a chest, a door) the game's own collision decides when NoClip ends; it pushes a character out of small overlaps.
- NoClip does not work while the Creative Mode mod runs: that mod flies the character itself, and Kiln's flight steps aside for it. `/noclip status` says so.
- A player who leaves the game while inside the ground is saved there. The game's Unstuck (in its menu) frees a character.
- Kicking, banning and the login event were tested with test connections on a test server, not with a real player's game.
- `Abilities.RemoveBuff` on a real player (the buff icon disappearing in the HUD) is a check of the guided client pass.
- The Windows launcher's own Python cooking a mod on Windows was not run by any test of this release: the tools and their unpacking are tested on Linux, and the Windows build is compile-checked.
- The cook on Windows (the tool run inside a job so that Cancel takes its child processes with it, and the check that a mod's files lie in its own folder) is compile-checked and was never run on Windows.
- The launcher does not cook mods you put into the game folder by hand, nor the mods of a local server it runs: `kiln cook` does that.
- The index files a cook writes next to its outputs (`audio.json` and the lists the Blocks compilers read) are not covered by a receipt.
- Equip, the chosen weather, tracked world writes, item data in players' games and affixes were proven on a test server with stand-ins for players. What a player sees is a check of the guided client pass for each.
- A weather hold does not outlast a server restart.
- Tracked writes work in a server world only (a dedicated server or a hosting game). A hook callback that writes in the middle of a step to an entity without a spawn time can have its write run after that step's structural changes; whether a player's entity has a spawn time is not known yet (if not, its writes behind a full step answer `Dropped` and are asked again).
- Item data in players' games: a game that acknowledges nothing gets nothing new (removals included) until the ten-second recovery, and then at its backed-off pace.
- Affixes: while the game refuses to end a player's stat change, that player gets no new affix bonus; with 64 such changes stuck on a server, nobody gets a new one until they clear (kiln.log says so).
- Baked definitions: statuses, effects, items, spells and talent blocks are not baked yet (the build prints "not baked" for them), so most Blocks mods still get them from the second start. When a baked file and the code differ, the baked file wins at every start until the mod is rebuilt; kiln.log warns.
- Kiln does not take over from a ShroudForge loader that the launch options start; it tells you.
- EMF: minimap draws nothing; Beastmaster's markers, buff reads and move reads do nothing; teleports has no map action.
- An EMF server set to refuse that also requires content mods still refuses a Kiln game: Kiln's list has no content entries yet.
- On Kiln an EMF mod's chat line always shows without a speaker's name, also a plain `chat_tell` (EMF shows that one under the player's own name).
- After leaving a server and joining another one without restarting the game, an EMF server's greeting is answered only when it arrives after the world has loaded (EMF greets 10 s and 45 s after you connect). When both come earlier, that session has no EMF mod messages and no mod check; rejoining fixes it.
- The services' new capability rows and change events were proven on test tables and on a test server with six test mods, not in a real player's game.
- KILN121 trusts the marks and reads one member at a time: a check in a helper of your own, in a field, or in another class's property is not seen, and a guard that is true for more than one reason (the service is there, or the mod is being baked) does not count as asking.
- The recording fakes were checked against the services' code and headers, never against a running game.
- The save editor's Deck tab and its new checks ran in the browser test bench only (Chromium), not in a real launcher window, on a real Deck or against a real save.
- A native service that appears only after Kiln's services started is found within about a second, except by Kiln.Hooks, Kiln.Build, the content service's link to the asset service, and the menu's craft-menu and render tables: those keep their first look for the whole process.
- If the launcher crashes or is killed while it cooks a mod, nothing is lost, but the mod can be left half-cooked. Its last good cooked files are set aside and come back at its next cook; until then they load only once a cook of the mod ends well. The mod's own `assets/assets.json`, `assets/cook.json` and `blocks/*.materials.json` stay as the stopped cook left them, which can make the mod read as changed. Press Play or "Cook again" to cook it afresh; in Copy mode, activating the profile again also copies a clean version from the Library.
- On Linux, if the launcher itself crashes during a cook, the cook tool it started keeps running until it finishes. It writes only into that mod's `assets/cooked` folder, and the next cook starts that folder from scratch.
- The cook tools check where they write, not what they read. A mod's recipe can name a source file outside the mod's folder, which the cook then reads with your rights; what it reads stays on your PC, and a stuck read is stopped by the cook's time limits. Install mods only from sources you trust, as with any mod that runs code.
- A handler's change that still waits for the next step when the same mod resets or reverts many values at once (a creature's whole state, a mod's content changes) is announced after that reset.
