# Kiln 0.2.0-dev.23

Three fixes for the launcher, found on a server that runs Kiln.Admin and the Emberwatch Lua mod together and after the in-app update to dev.22.

## Players and server owners

- **The Servers page no longer fails after a start.** On a server that also runs the Emberwatch Lua mod (a ShroudForge mod, which Kiln's ShroudForge support now starts), the page showed "This page failed: (n.state?.players??[]).filter is not a function". That mod writes an empty player list as `{}`, and the launcher had taken its file bridge because Kiln.Admin was not up yet. The launcher now reads such a state, and moves to Kiln.Admin's own connection as soon as that answers.
- **Two admin mods in one folder are reported.** Kiln.Admin and the Emberwatch Lua mod answer the same folder (`shroudforge/exports/emberwatch`). With both installed, each request is answered by whichever reads it first. Kiln.Admin now writes a warning to kiln.log when it finds the other one's state file. Remove `mods/emberwatch-admin` (Kiln.Admin does its work), or give Kiln.Admin a folder of its own with `"bridge"` in `kiln/data/kiln-admin/config.json`.
- **No more rewrite loop after an update.** After the restart into dev.22, the old launcher could stay alive in the background for a while. The two versions then wrote the game's `kiln/profile.json` in turns, about twice a second, until the game was started. A launcher that is closing or restarting now stops its background work at once and ends for sure within five seconds, and a running launcher answers a foreign change of `profile.json` at most three times a minute.

## Known limits

- Not run on Windows or a Steam Deck.
- The update from dev.21 or dev.22 to this build still starts from the old launcher, so the old one can linger one more time; the new one no longer answers it without end.
