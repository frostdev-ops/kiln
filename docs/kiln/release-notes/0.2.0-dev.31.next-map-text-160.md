# Kiln 0.2.0-dev.31.30: a mod's map marker can show its own name in the map's tooltip (GitHub #160)

A mod's marker on the world map can now show its own name in the game's map tooltip, instead of the icon type's name
("Custom marker" for every chest pin). Players see this only with a mod that uses it (Kiln.Markers'
`MarkerMapLabel.NativeTooltip`). Mod markers on the map also keep their own icons when one moves past another. Neither
needs a mod API change.

## Players and server admins

- **Mod markers can carry their own names on the map.** Hover a mod's marker on the world map and the game's tooltip
  shows the name the mod gave it ("Golden chest 3"), in the game's own font and style. You see this only with a mod that
  uses it; every other mod marker shows what it showed before, and the game's own markers and your own map pins keep
  their names.
- **Shown like a name a player typed.** The game's text filter applies when the game has one. Chinese, Japanese and
  Korean names are drawn with the game's own fonts.
- **Mod markers keep their own icons.** When one mod marker came nearer to you than another (a marker that follows a
  creature or a player, for one), two markers with different icons could show each other's icons on the map until the
  map redrew its markers (a marker added or removed, for one). Each mod marker now keeps its place in the game's map
  list, and with it its icon.
- **Known issue: a changed icon.** When a mod gives a marker another icon while the number of map markers stays the
  same, an open map can keep the old icon until a marker is added or removed or the map's filter is used. The name in
  the tooltip changes at once. This is older than this release.
- **On a server.** A server mod can send such markers too. A player gets them when their Kiln is this version or newer;
  a player on an older Kiln does not get those markers at all, unless the server mod also sends them a plain one. The
  server itself needs nothing new: the map is the players'.
- **Thanks** to cykel-far for the request and the precise report of what the tooltip showed (kiln#160).

## Modders

- **No mod API change** for this: no signature or enum change. `MarkerMapLabel.NativeTooltip` and the
  `markers.map_text` row were already in the API; until now the row was always off and `Markers.Set` with
  NativeTooltip threw `KilnUnavailableException`.
- **What turns it on.** `markers.map_text` is on on a game client when `markers.map` is on and the new client sigdb
  feature `markers.map_tooltip_text` resolves (Steam build 26430625 has it). Where it does not, the row stays off with
  the reason, `Set` keeps throwing `KilnUnavailableException` naming `markers.map_text` (set the marker with
  `MarkerMapLabel.None` then), and kiln.log says once at start "markers: the game's map tooltip cannot be found on this
  build (markers.map_tooltip_text): MapLabel.NativeTooltip is refused (markers.map_text off), map icons keep the game's
  own names".
- **How the game shows `Text`.** As the tooltip's title, through the game's own path for names players type: its text
  filter when it has one, and `<` and `\` escaped, so markup shows as typed. Kiln's text rule applies (at most 128
  bytes of UTF-8, one line). An empty `Text` leaves the icon type's own name. Two icon types name themselves: on
  `tower_locked` (Ancient Spire) the title stays "Ancient Spire" and `Text` is the line under it, and on
  `playerwatersource` (Water Source) the tooltip always says "Water Source". `MarkerMapLabel.None` (the default) leaves
  the tooltip as it was: "Custom marker" for the `icon_*` pins, the type's name or nothing for the others.
- **Server sends.** `Markers.Send` takes `MarkerMapLabel.NativeTooltip` now (it threw before). The marker goes to the
  players whose Kiln offers the tooltip in its marker handshake (their `markers.map_text` on, with a verified map);
  every other player is refused for it (counted in `Refused`; the result is `Partial`, or `RequiresClient` when nobody
  took it), so nothing is drawn partly. For a fallback, send those players the same key with `MarkerMapLabel.None`
  (`Markers.Send(player, ...)`). A dedicated server's own `markers.map_text` row is `WrongSide`, as `markers.map`. The
  marker channel stays v1.
- **The map's slot order.** Kiln's map rows now go into the game's map list in a fixed order (local before received,
  then mod id, generation and key) instead of best first. The game keeps each slot's icon until the number of map
  markers changes, so rows that changed places as the camera or a followed marker moved showed each other's icons.
  Which markers get onto the map when room is short is unchanged (`Priority`, then distance from the camera), and so
  are `VisibilityChanged` and the compass and world surfaces.
- **How it works.** Each row of the game's map list has a text field the game fills for a named object (an entity's
  player-given name); the game's name for a map entry takes that field before anything else, and the hover tooltip
  starts from that name. kiln.markers fills it in its own rows only (the record's text in its arena, never moved or
  freed while the game runs, at most 4 MiB in all) and calls or hooks nothing of the game's UI. Rows with
  `MarkerMapLabel.None` hold byte for byte what 0.2.0-dev.31.29 wrote; only their order in the list changed (above).
  Static analysis of client 26430625 in docs/re/map.md, "The tooltip's name", "The tooltip text" and "The layer keeps a
  slot's icon".
- **Tests.** The entry's text field and the game's hash of it, Kiln's and the game's rows named over the game's clear
  and refill at every frame, a moved, renamed and removed marker, 128-byte and CJK text, the row on and off, the map's
  slot order while the camera and a followed marker move (`surfaces_test`); the store with the row on (`store_test`); a
  server's NativeTooltip marker reaching only the players whose Kiln shows it, and the per-player fallback
  (`link_test`); the rows on a dedicated server and a client (`ready_test`).
  `tools/sigport/tests/test_markers_map_text.py` pins the static facts on the client exe.

## Not yet seen in a real game

- **The tooltip.** Nobody has hovered a marker with this build yet. It rests on static analysis of client 26430625 and
  host tests; cykel-far offered to test a dev build in single player.
- **CJK names.** Chinese, Japanese and Korean names in the tooltip of an English game: the game's default font group
  carries Noto Serif SC and KR for them, but that was not watched.
- **The icons.** Mod markers keeping their icons as they move past each other rests on the same static analysis.
- **Mixed servers.** A server's NativeTooltip markers on a dedicated server with players on this and on older Kiln
  versions.
