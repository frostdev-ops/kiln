# Kiln 0.2.0-dev.31.next: a mod's map marker can show its own name in the map's tooltip (GitHub #160)

A mod that puts markers on the world map can now have the game's own tooltip show each marker's name when the cursor is
on it, instead of the icon type's name ("Custom marker" for every chest pin). Players see this only with a mod that asks
for it.

## Players and server admins

- **Mod markers on the world map can carry their own names.** Hover a mod's marker on the map and the game's tooltip
  shows the name the mod gave it ("Golden chest 3"), in the game's own font and style, as it shows a place's name. You
  see it only with a mod that uses this (Kiln.Markers' `MarkerMapLabel.NativeTooltip`); every other mod marker shows
  what it showed before, and the game's own markers and your own map pins keep their names.
- The game shows the name as it shows a name another player typed: its text filter applies when the game has one, and
  Chinese, Japanese and Korean names are drawn with the game's own fonts.
- **On a server:** a server mod can send such markers too. A player gets them when their Kiln is this version or newer;
  a player on an older Kiln does not get those markers at all, unless the server mod also sends them a plain one. The
  server itself needs nothing new: the map is the players'.
- **Thanks** to cykel-far for the request and the precise report of what the tooltip showed (kiln#160).

## Modders

- No mod API change: mod API 0.2.26, and no signature or enum change. `MarkerMapLabel.NativeTooltip` and the
  `markers.map_text` row were already in the API; until now the row was always off and `Markers.Set` with
  NativeTooltip threw `KilnUnavailableException`.
- **What turns it on.** `markers.map_text` is on on a game client when `markers.map` is on and the new client sigdb
  feature `markers.map_tooltip_text` resolves (Steam build 26430625 has it). Where it does not, the row stays off with
  the reason, `Set` keeps throwing `KilnUnavailableException` naming `markers.map_text` (set the marker with
  `MarkerMapLabel.None` then), and kiln.log says once at start "markers: the game's map tooltip cannot be found on this
  build (markers.map_tooltip_text): MapLabel.NativeTooltip is refused (markers.map_text off), map icons keep the game's
  own names".
- **How the game shows `Text`.** As the tooltip's title, through the game's own path for player-written names: its text
  filter when it has one, and `<` and `\` escaped, so markup shows as typed. Kiln's text rule applies (at most 128 bytes
  of UTF-8, one line). Two icon types name themselves: on `tower_locked` (Ancient Spire) the title stays "Ancient Spire"
  and `Text` is the line under it, and on `playerwatersource` (Water Source) the tooltip always says "Water Source".
  `MarkerMapLabel.None` (the default) leaves the tooltip as it was: "Custom marker" for the `icon_*` pins, the type's
  name or nothing for the others.
- **Server sends.** `Markers.Send` takes `MarkerMapLabel.NativeTooltip` now (it threw before). The marker goes to the
  players whose Kiln advertises the tooltip in its marker handshake (their `markers.map_text` on, with a verified map);
  every other player is refused for it (counted in `Refused`; the result is `Partial`, or `RequiresClient` when nobody
  took it), so nothing is drawn partly. For a fallback, send those players the same key with `MarkerMapLabel.None`
  (`Markers.Send(player, ...)`). A dedicated server's own `markers.map_text` row is `WrongSide`, as `markers.map`.
- **How it works.** Each row of the game's map list has a text field the game fills for a named object (an entity's
  player-given name); the game's name for a map entry takes that field before anything else, and the hover tooltip
  starts from that name. kiln.markers fills it in its own rows only (the record's text in its arena, which is never moved
  or freed while the game runs) and calls or hooks nothing of the game's UI. Rows with `MarkerMapLabel.None` are byte for
  byte what 0.2.0-dev.31.29 wrote. Static analysis of client 26430625 in docs/re/map.md, "The tooltip's name" and "The
  tooltip text".
- Host tests: the entry's text field and the game's hash of it, Kiln's and the game's rows named over the game's clear
  and refill at every frame, a moved, renamed and removed marker, 128-byte and CJK text, the row on and off
  (`surfaces_test`); the store with the row on (`store_test`); a server's NativeTooltip marker reaching only the players
  whose Kiln shows it, and the per-player fallback (`link_test`); the rows on a dedicated server and a client
  (`ready_test`). `tools/sigport/tests/test_markers_map_text.py` pins the static facts on the client exe.

## Not yet seen in a real game

- Nobody has hovered a marker with this build yet. It rests on static analysis of client 26430625 and host tests;
  cykel-far offered to test a dev build in single player.
- Chinese, Japanese and Korean names in the tooltip of an English game: the game's default font group carries Noto
  Serif SC and KR for them, but that was not watched.
- A server's NativeTooltip markers on a dedicated server with players on this and on older Kiln versions.
