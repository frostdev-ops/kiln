# Kiln 0.2.0-dev.31.22

A mod's setting can now go past the end of its slider when the mod allows it, on the Kiln menu's config page and in the launcher. A mod asset whose hash Kiln cannot read is now an error in kiln.log that names the file, instead of content the game never finds.

## Players and server admins

- **A mod's setting can go past the end of its slider when the mod allows it.** On the Kiln menu's config page and in the launcher, a setting whose mod marks that end of its range as soft (for example a cost multiplier with a slider from 0 to 1) now takes a typed 2 or 3 in the number field beside the slider, and a value like that in the config file is kept instead of being clamped back with a warning. The slider stays at its end for such a value; dragging it gives a value of the slider's range again. Settings whose mod did not mark a soft end work as before. Thanks to fafawanji for the request (#155).
- **A mod asset with a hash Kiln cannot read now says so.** A mod that serves its own data under a hash it names in its `assets/assets.json` still loaded when Kiln could not read that hash (a size written in hex, for example): the data went in under another hash, kiln.log counted no error, and the game then found nothing ("Could not find content"). That entry is now an error in kiln.log naming the mod's file, and the mod's other assets still load. A hash that names another size than its file was already refused; its kiln.log line now gives both sizes instead of "failed". Only the mod's author can fix such a hash (below).

## Modders

- Mod API 0.2.26 (was 0.2.25): additive only, `RangeAttribute.SoftMin` / `SoftMax` (get, set) and `ConfigEntry.SoftMin` / `SoftMax` (get, init). The MDK packs are 0.2.0-dev.31.22.
- **Soft range sides for configs (#155).** `[Range(0, 1, 0.1, SoftMax = true)]`: `RangeAttribute.SoftMin` / `SoftMax` (named arguments) make that side end the slider only: a value past it, typed into the number field, read from the file, set with `TrySet` or sent by a server, is kept as it is, with no refusal, no clamp and no warning; only the number's own type still bounds it. The other side stays hard as before (a typed -1 is refused with `"costMultiplier" must be in 0..max (got -1)`, a -1 in the file is clamped with the usual warning). `ConfigEntry.SoftMin` / `SoftMax` and the live and offline schemas' `softMin` / `softMax` (written only when true) carry it; the file's meta line reads `Range: 0 .. 1 (slider; higher values allowed)` (`Range: 1s .. 1m (higher values allowed)` for a duration or a list, which have no slider). Durations and lists of numbers follow the same rule, a `[Command]` argument has no bound on a soft side, and a UI block's `set` action or slider `min` / `max` may go past it. A `decimal` entry is bounded by the decimal type there (about ±7.9e28). The step stays the third argument: `Step = 0.1` as a named argument cannot compile (`Step` is a `double?`, which C# does not take as a named attribute argument), so write the step positionally. A mod that uses the flags needs mod API 0.2.26, which the 0.2.0-dev.31.22 SDK writes into its manifest. Thanks to fafawanji for the request (#155).
- **kiln.assets reads a blob's `hash` exactly.** In `assets/assets.json` a blob entry's `hash` is the text `ContentHash.ToString()` writes, `<decimal size>-<h0>-<h1>-<h2>`: the size in decimal, each word 1 to 8 hex digits, nothing before, between or after. Any other `hash` (a size in hex, a space or sign, a value that is not a string) is now an error of that entry, `blob <file>: bad hash … (want <decimal size>-<h0>-<h1>-<h2>)`, and a file of another length than the hash says is one too, `blob <file>: its hash says <n> bytes, the file has <m> (the size is decimal)` (it was `blob <file>: failed`). The manifest's other entries still load. Up to 0.2.0-dev.31.21 a hash kiln.assets could not read was served under the hash it derives from the file's bytes, with "errors 0", and the game then found nothing under the hash the mod named ("Could not find content"). `Assets.Dump("blob:…")` reads the same text. The doc comments of `kiln_assets.h`'s dump and of TestKit's `FakeBlobRegistration.Hash` now say the size is decimal (no API change).
- `kiln lint` flags such a hash as KL106 (now also a size of more than 10 digits) and a size that is not the file's as KL504.
- `kiln-vfxcook cook` writes its `assets.json` blob hashes in that spelling; they had the size in hex, so cook a VFX mod's assets again with this kiln-vfxcook. Its file names and report keep the cook's own all-hex spelling.

## Not yet seen in a real game

- The in-game config page with a soft-max setting past its slider's end: the slider's grab at its end with the real value on it, typing 3 into the number field, Apply, and the value after a reload (host tests over a fake kiln.ui table only).
- The launcher's config editor with such a value (unit tests of the form only).
- A mod whose `assets.json` has a blob with a bad hash, in a game or on a server: host tests of the entry's rule and the Windows build only.
