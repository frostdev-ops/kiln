# Kiln 0.2.0-dev.28

(In work. Each section is filled as its packages merge; the summary line is written last.)

## Mod authors

- **The mod API is 0.2.3.** Everything new is additive: no public member of 0.2.0-dev.27 was removed or changed.

### OnBoot: content that is there on the first start
- Set `"boot": true` in `kiln.mod.json` and stage statuses, effects, items, spells and talents in `Mod.OnBoot` with `BootDefinitions.For(boot).Define(...)`. They exist before the game reads its data, on the very first start, with the same ids a runtime `Define` gives them. `Mods.BootState(id)` says whether a mod's boot content made it.
- `"boot": "required"` makes a start stop with a clear message when that mod's boot content cannot be applied, instead of loading a world without it. A broken boot mod that is not required is left out and named in kiln.log; it never half-loads.
- Only those five kinds of block can be staged at boot in this release; the others answer `NotInBootKinds` and still work as runtime blocks in `OnLoad`.
- On a world a player hosts, OnBoot is switched off until its game test (`mods.boot.client`); a dedicated server has it.

### Resource patches: the game's own data, changed before it is read
- A boot mod can change fields of the game's data before the game reads them, for example the balancing table's experience per level or Flame Altars per flame level. Use `resourcePatches` in a blocks file or a `ResourcePatchBlock` in `OnBoot`; paths take `[*]` for every element, and values take a number or `mul`, `add`, `min` (at least) or `max` (at most). Numbers, bools and enums only. [resource-patches.md](../modding/resource-patches.md)
- A change made in `OnLoad` came too late for such data: the game had already read it. A patch is checked before the start and written when the game's resource service is up and nothing has read from it yet.
- Both sides need the mod. When a required boot mod's patch cannot be applied, the start stops with the reason in boot.json instead of loading a world without it.
- `IReadOnlyGameData` in `OnBoot` reads the game's own data (items, templates, skills, materials) from the boot snapshot ([boot-gamedata.md](../modding/boot-gamedata.md)). Kiln makes the snapshot from the game's files at Play when an enabled mod boots: about 30-45 s and 200 MB once per game update.
- On a world a player hosts, `mods.boot.resource_patches` is switched off until its game test; a dedicated server has it.

### Update checks for your mod
- Name your GitHub repository in `updates` in `kiln.mod.json`, and players get update notices in the launcher and from `kiln updates check`. A release made with `kiln publish` carries everything the check needs. [updates.md](../modding/updates.md)
- A value Kiln cannot read in `updates` is a warning and is ignored; it never stops your mod loading.

### Settings in OnBoot
- `Config.Register<T>()` and its `Value` work in `OnBoot`: a boot mod can stage with a number from its settings (a level cap, an altar count). Writing a setting, `Reload` and `Changed` are for `OnLoad`; in `OnBoot` they say so.
- A call that needs the game's tick says, in `OnBoot`, which member refused and that it belongs in `OnLoad`.
- Kiln.Sdk: `<KilnBoot>true</KilnBoot>` (or `required`) writes `"boot"` into the generated `kiln.mod.json`.

### Publishing a mod
- `kiln publish` releases a packed mod as a GitHub release in two steps: a plan you read (the zip is checked for game data, cooked files, saves and secrets, then frozen) and an apply you confirm, which makes a draft with the zip, its checksum and a `kiln-release.json`. A third step makes the draft public. A run that stopped resumes without uploading anything twice. [publishing.md](../modding/publishing.md) has the whole of it.
- The token is read from your system's credential store (`kiln publish --store-token github` puts it there, read from standard input). Where there is no store, a CI job for example, it is read from the environment variable `KILN_PUBLISH_GITHUB_TOKEN`. It is never written to the plan, the journal, a log or an error.
- Not yet tested against GitHub itself, only against recorded answers: make your first release to a repository you can delete ("The first real run" in the guide).
- An uploaded file whose answer carries no checksum is downloaded once (bounded) and hashed before `--resolve-step` adopts it, and the journal is written through to disk before each step on Unix and Windows.

### Questions about the world
- `Kiln.Queries` answers on the server: the first terrain or building voxel on a segment (`RaycastVoxels`), the ground below a point (`GroundBelow`), voxel line of sight between two entities (`VoxelLineOfSight`), and the entities whose origin is inside a sphere or a box. [queries.md](../services/queries.md)
- An answer is a hit, a miss or "unknown" (the terrain there is not loaded): a ray never reports open space it could not read.
- Voxel rays do not see props or creatures. All mods together share 64 rays and 500 microseconds of ray time in a server step; a call beyond that answers `BudgetExceeded`, which means "next step".
- A creature brain can ask for line of sight: `Perception = new NpcPerceptionPolicy { Occlusion = NpcOcclusionMode.Voxels }`, or `"perception": { "occlusion": "voxels" }` in a block file. What is behind terrain or a building is then not in `Seen`, and what could not be checked is not seen either. `npc.PerceptionStats` says why. [npc-blocks.md](../modding/npc-blocks.md)
- Kiln.TestKit has a fake for the queries (`kiln.Queries`): this code runs under `dotnet test`.

### Paths
- `Queries.FindPath` asks the game's own path search, the one its creatures use, for a walking route between two points at most 200 m apart; `Queries.CanReach` asks only whether one arrives. The answer comes some server steps later and is a copy of the route's points from the step the game answered. [queries.md](../services/queries.md#paths)
- Nothing is moved: a brain walks the points itself, one after another with `MoveTo`. `MoveTo` alone is not pathfinding; it walks straight at a point.
- A request names an anchor entity with the game's spawn marker; for a player or a saved entity, spawn a helper pickup and use that (the guide says how). At most 32 requests are open at once, 8 for one mod; a request ends after 10 s and 150 steps.
- On a world a player hosts, `queries.path` and `queries.reachability` are switched off until their game test (`02-queries.path-hosted`). A dedicated server has them.

### Game types, content blobs, scale
- `GameType.ImpactName`, `GameTypes.ByImpactName` and `FindAllByImpactName` find a game type by the name Impact scripts use (`ecs.Health`). Capability `types.impact_names`.
- `Assets.OpenBlobCatalog` lists every content blob the game serves, the game's own and every mod's, with where each comes from and whose bytes are served. Capability `assets.blob_catalog`; sample `BlobCatalog`.
- `World.SetTransformScale` sets an entity's scale for each axis as one tracked write. It changes the drawn size, not collision. On the test server the scale of a placed prop did not survive a restart: set it again when the world starts. Capability `world.transform_scale`, switched off until its game test (`13-world.transform-scale`), on a server as well; sample `TransformScale`.

### Terrain overlays
- `Kiln.Terrain` puts a bounded patch of ground into the world: an ore vein, a mound, a tunnel, a small dungeon shell, as a C# record (`TerrainPatch`) or JSON. `Terrain.Apply` writes it once per world, a batch each tick, and remembers which mod owns it and at which version. [terrain.md](../services/terrain.md) has the whole of it, the sample `OreVein` an ore vein.
- The cells are ordinary world edits: the game saves them and sends them to every player, also to a player without Kiln. A version of a patch never writes over ground a player changed since the last one; `Terrain.Inspect` says what `Apply` would do and writes nothing.
- Game materials only: a player without the mod has no look for a material of a mod's own, so a patch refuses one.
- On a world a player hosts, `terrain.overlays` is switched off until its game test (`19f-overlay-client`). A dedicated server has it.
- Removing a mod leaves its ground where it is (`Terrain.Forget` only drops the record). Two mods' patches are kept apart only while both are installed.
- `Build.WriteIfUnchanged` writes only if the world still holds the cells you read when the write commits, after every `BuildEditingEvent` handler; otherwise it returns `BuildRefusal.Changed` and writes nothing. Terrain overlays write this way: a change another mod makes to the same spot while an overlay is applied is kept, and the overlay gives up that block.

### Weapon moves: follow-ups
- A weapon's move can say where its follow-up windows lead. `MoveBlock.FollowUps` points a window the motion already has (`Primary`, `Heavy`, `Block`, `Parried`) at another move of the same weapon: a block that goes on into the weapon's own parry, for example.
- A weapon with follow-ups gets all its moves or none of them. `Blocks.MovesStatus` says which (`MoveApplicationResult`), and `WeaponMovesApplicationChangedEvent` says when that changes; unloading the mod takes the moves off again.
- If a switch to new moves fails part way and the old ones cannot be put back, `Blocks.MovesStatus` says so (the slots are mixed; no generation is applied) instead of naming the old generation. A switch is not rolled back atomically yet.
- `blocks.move_followups` is switched off until its game test (`16c-b`, `16c-d`), on a server as well: what decides is what a player sees. `"preview"` in `kiln.json` switches it on.

### Network
- `NetPeer.FramesIn` and `NetPeer.FramesOut` count the frames each player's game and the server have sent on Kiln's channel.
- Kiln's own services can now hold a joining player with Kiln at the door, before the world is theirs: at most 25 s, with frames flowing both ways while they wait, and then let them in or refuse them with a reason. Capabilities `net.admission` and `net.gate.hold_all`. Mods use this through the services built on it in later releases, not directly.

### Tool wear
- `ToolBlock.WearPerDebit` and `Items.SetToolWearPerDebit(tool, n)` make each of the game's wear debits of an axe or pickaxe cost `n` instead of 1 (0 to 32767). It counts per debit, not per swing: two debits spend twice, and a swing the game does not debit spends nothing. Rules last while the game runs and go with their mod. `Items.ToolWearStatus`, `ToolWearRuleChangedEvent` and `ToolDurabilityChangedEvent` say what is in effect and what changed.
- On a world a player hosts it is switched off until its game test (`16b-g`); a dedicated server has it.

### Values in the game's own UI
- Client mods can replace the numbers and bars the game draws for an item (the detail view, an inventory slot, the held item) and the local player's health, stamina and mana with `Ui.Values`. It changes the picture only, never the values themselves. They can add lines to Kiln's Item details window and read the slots the game drew each frame.
- Every part of it is switched off until its game test (`05a-c1` to `05a-c5`).

### Block kinds of your own
- A mod can add a kind of block of its own (`Blocks.RegisterKind`): other mods then write that block in C# or in `blocks/*.json`, and Kiln turns it into its own items, weapons, spells, statuses and effects. A block that is refused part way leaves nothing behind.
- A plan with parts that wait for content ready (every item plan has some) stays `PendingContent`, with nothing published, until those parts are done; then it is `Applied`. A part that fails refuses the plan with `ContentReadyFailed` and its reason, and what it registered is taken back.
- Kiln.Blocks reports its capability rows at its first use: in `OnLoad`, before the first call into `Blocks`, `Capabilities.Is("blocks.…")` still answers false. Use the call itself and its `KilnUnavailableException`.

### Creature control
- `Kiln.CreatureControl` (server) lets a mod take a lease on a creature: while the lease drives, the game's AI is off and the steering that overwrote movement input is removed; both come back on release. Roles decide who wins, and a refusal comes back as a result with its reason. Sample: `CreatureControlSample` (`/hold`, `/pacer`).
- A body the broker cannot give back is removed, and if the broker itself stops, every body it holds is removed at the next step. Since this release that includes creatures run by a mod's brain.
- Sample `NpcSample` now has a brain that walks a path found with `Queries.FindPath`.

### Capabilities that wait for their game test
- Some of what this release builds can only be confirmed in a real game, and ships switched off until it has been. Such a capability reads `unavailable` with the reason `policy` and the text `game test pending:` followed by the guided checks that open it. `Capabilities.IsHeld(name)` and `Capability.IsHeld` tell "built, not tested yet" from "does not work here".
- `"preview"` in `kiln.json` switches held capabilities on before then: `true` for all of them, or a list of names (`"preview": ["camera.fov"]`). Use it on a test server or in your own game, not on a server other people play on.

## Players

- The launcher can tell you when a mod has a newer version: press Check for updates above your mods, or switch on "Check for mod updates once a day" in Settings (off by default). A notice is only a link to the mod's page; nothing is downloaded, installed or switched for you. A mod's menu has Updates…, where you see what the last check said or tell Kiln where a mod is published.

- Mods can show their own numbers and bars in the game's item details, slots and HUD, once those parts pass their game test.
- Mods that add items, spells or talents can have them ready on a server's first start, with no second restart.
- Mods can make an axe or pickaxe wear faster, slower or not at all on dedicated servers; hosted worlds follow after the game test.
- Mods that change values the game reads once at its start (experience per level, how many Flame Altars a base may have) now work from the first start; before, their change came too late.
- A server may keep you on the loading screen a little longer while its mods check your game; after at most 25 s you either join or get a message saying why not.
- Mods can now add small landforms and ore veins that stay after a restart, and that you see without any mod of your own when you join a server that has them.

## Server operators

- `kiln/config/kiln.queries.json` sets how many voxel rays all mods together may cast in a server step and how much time they may take (64 rays and 500 microseconds unless you change it). It is read once, at the start.

## Fixed

- Kiln mods no longer stop working when another loader has changed the game's code in place before Kiln starts: Flame's Creative Mode 3.2.0 and Greeneye's The Worst Map Mod switched off up to 22 of Kiln's features that way (moving items, chat, mod screens, player rules), so mods that showed as loaded did nothing. Kiln now reads the game's functions from the exe file in that case and says in kiln.log which places another mod patched. Confirmed by the guided check `00-sigdb.in-place-patches`.
- A creature driven by a mod's own brain (`Brain = () => new MyBrain()`, or `"brain"` in a block file) now walks. Before, the game's own steering overwrote `MoveTo` and the creature stood still. Kiln.Blocks now takes the body from the game's AI while the brain runs (`MoveTo`, `Stop` and `Face` act only while it has it) and gives it back when the brain stops or its mod unloads.

## Built, game test pending

What this release carries switched off because only a real game can confirm it. Each entry names the capability and
the guided checks that open it; `"preview"` in `kiln.json` switches one on by name before then.

## Known limits

- **Play once** (a single start of a mod set without changing your profile) does not make the boot snapshot. An OnBoot mod that reads the game's data finds it "not ready" on such a start, unless a snapshot of this game version exists already; one normal Play with the mod enabled makes it.
- **Terrain overlays:** a first install over ground that already holds the plan's result is refused as if a lost ledger had been found (the ground is the only evidence Kiln has); `Forget` first makes it a first install.
- **Block kinds:** a later reload of the game's content replays an applied plan's rules, and an error then is only logged. Expansion of nested effects has no work budget yet.
