## Mod authors

- **The mod API is 0.2.3.** Everything new is additive: no public member of 0.2.0-dev.27 was removed or changed.

### Publishing a mod
- `kiln publish` releases a packed mod as a GitHub release in two steps: a plan you read (the zip is checked for game data, cooked files, saves and secrets, then frozen) and an apply you confirm, which makes a draft with the zip, its checksum and a `kiln-release.json`. A third step makes the draft public. A run that stopped resumes without uploading anything twice. [publishing.md](../modding/publishing.md) has the whole of it.
- The token is read from your system's credential store (`kiln publish --store-token github` puts it there, read from standard input). Where there is no store, a CI job for example, it is read from the environment variable `KILN_PUBLISH_GITHUB_TOKEN`. It is never written to the plan, the journal, a log or an error.
- Not yet tested against GitHub itself, only against recorded answers: make your first release to a repository you can delete ("The first real run" in the guide).

### Questions about the world
- `Kiln.Queries` answers on the server: the first terrain or building voxel on a segment (`RaycastVoxels`), the ground below a point (`GroundBelow`), voxel line of sight between two entities (`VoxelLineOfSight`), and the entities whose origin is inside a sphere or a box. [queries.md](../services/queries.md)
- An answer is a hit, a miss or "unknown" (the terrain there is not loaded): a ray never reports open space it could not read.
- Voxel rays do not see props or creatures. All mods together share 64 rays and 500 microseconds of ray time in a server step; a call beyond that answers `BudgetExceeded`, which means "next step".
- A creature brain can ask for line of sight: `Perception = new NpcPerceptionPolicy { Occlusion = NpcOcclusionMode.Voxels }`, or `"perception": { "occlusion": "voxels" }` in a block file. What is behind terrain or a building is then not in `Seen`, and what could not be checked is not seen either. `npc.PerceptionStats` says why. [npc-blocks.md](../modding/npc-blocks.md)
- Kiln.TestKit has a fake for the queries (`kiln.Queries`): this code runs under `dotnet test`.

### Game types, content blobs, scale
- `GameType.ImpactName`, `GameTypes.ByImpactName` and `FindAllByImpactName` find a game type by the name Impact scripts use (`ecs.Health`). Capability `types.impact_names`.
- `Assets.OpenBlobCatalog` lists every content blob the game serves, the game's own and every mod's, with where each comes from and whose bytes are served. Capability `assets.blob_catalog`; sample `BlobCatalog`.
- `World.SetTransformScale` sets an entity's scale for each axis as one tracked write. It changes the drawn size, not collision. On the test server the scale of a placed prop did not survive a restart: set it again when the world starts. Capability `world.transform_scale`; sample `TransformScale`.

### Capabilities that wait for their game test
- Some of what this release builds can only be confirmed in a real game, and ships switched off until it has been. Such a capability reads `unavailable` with the reason `policy` and the text `game test pending:` followed by the guided checks that open it. `Capabilities.IsHeld(name)` and `Capability.IsHeld` tell "built, not tested yet" from "does not work here".
- `"preview"` in `kiln.json` switches held capabilities on before then: `true` for all of them, or a list of names (`"preview": ["camera.fov"]`). Use it on a test server or in your own game, not on a server other people play on.
