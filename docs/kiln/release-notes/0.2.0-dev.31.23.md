# Kiln 0.2.0-dev.31.23

A spell or arrow you pick from a mod's HUD list, such as Grimoire's, now stays under the cursor instead of flickering back to the one before it for a moment. Testers can switch on a pick trace that follows each pick in kiln.log.

## Players and server admins

- **A mod's spell or arrow no longer flickers back to the previous one after you pick it.** With a mod that puts its own spells or arrows in the HUD list (Grimoire, for example), the picker moved to the spell you picked, showed the spell you had before for a moment, then went back. The game keeps putting the list's cursor on the equipped spell until the mod's swap of the new spell arrives: a short moment when you play alone (longest in the first switches after a start) and a network round trip more on a dedicated server. Kiln now keeps the cursor on your pick until the swap arrives, for up to a second, so the next scroll step also starts from the spell you picked. A swap that never comes leaves the equipped spell after that second, as before. Thanks to Fuzen777 for the report and the trace from Grimoire (#151).
- **New for testers: a pick trace in kiln.log.** It follows each pick of an arrow or spell row for 2 seconds, frame by frame: the pick, the game's own choice, each build of the list and what the HUD drew (lines `ui.ammo trace: ...`). It is off by default. To switch it on, quit the game, open `kiln.json` in the `kiln` folder next to the game's `enshrouded.exe` (on Windows for example `C:\Program Files (x86)\Steam\steamapps\common\Enshrouded\kiln\kiln.json`; Steam: Enshrouded, Manage, Browse local files), add `"ammoTrace": true` inside its `"ui"` section (a file with nothing else in it reads `{ "ui": { "ammoTrace": true } }`; with a `"ui"` section already there, put the key into that one, for example `"ui": { "look": "game", "ammoTrace": true }`), save, and start the game. On Linux with Proton the same file works, or `KILN_AMMO_TRACE=1 %command%` in the game's launch options in Steam (Steam's launch options cannot set it on Windows). `kiln/logs/kiln.log` then says `ui.ammo: the pick trace is on` near the top. Remove the key afterwards. How to read the lines: [docs/kiln/ui.md](../ui.md#tracing-a-pick-of-the-list-testers).

## Modders

- No mod API change: mod API 0.2.26, as in 0.2.0-dev.31.22. The MDK packs are 0.2.0-dev.31.23.
- **A `Ui.AmmoList` row's pick keeps the cursor until its swap arrives (#151).** The cursor of a pick that raises `Picked` now stays on that row over the game's selection sync (`client_cycle_inventory_stock`, most frames), which put it back on the equipped item because such a pick writes no pending pick of the game's. It holds until the game itself names that item (your server half's swap arrived), the player picks a row that goes to the game, the list is cleared, the provider retires, the client session, world or player changes, or 1 s passes. Another held weapon keeps it: the equipped arrow or spell is the player's slot, and the game's own pending pick holds over a weapon change the same way. This applies in `Append` and `Replace`, only while your rows are up, and there is nothing to call. When your new rows no longer list the item under the cursor, the list takes the game's own selection instead of none (with none, the HUD drew the index it drew last). On a game build where kiln-tools' new hook `ui/AmmoSelectAction` (sigdb feature `ui.ammo.cursor`) does not resolve, only the list's builds hold the pick and kiln.log says so once at the start. The test kit's `KilnHarness.AmmoList` already kept `Selected` on the picked item. Thanks to Fuzen777 (#151).
- The pick trace above (`kiln.json` `"ui": {"ammoTrace": true}` or `KILN_AMMO_TRACE=1`, which wins and where `=0` turns it off; read once at the start) names for each pick where it came from (the scroll, the direct selection, or elsewhere in the game) and who took it, the game's choice in its selection sync and its finalizer, each build's cursor at entry, the game's own and at exit, which rows the build showed (the current publication, rows kept over a newer build, or the game's own and why) and the index and item the HUD drew, with the pick's number, the time since it and a frame count on every line. A step writes a line only when what it saw changed, a repeat of the same pick is not a new one, and at most 100 lines a second go to kiln.log. The HUD list draw (`ui/AmmoListDraw`, sigdb feature `ui.ammo.trace`) is hooked only while the trace is on.

- Which of the game's selection sync, list build and HUD draw runs first in a frame, and so on how many frames the previous spell was drawn. The trace's `sync`, `build` and `draw` lines show it.
- The pick trace itself in a game.
