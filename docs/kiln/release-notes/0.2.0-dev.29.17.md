# Kiln 0.2.0-dev.29.17

Play a copy of the game Steam doesn't know, without Steam; production stations' finished items as stock for fills and crafts; a fix for stutters on hard drives; and a new SDK (mod API 0.2.9) with resource patches that copy components and replace lists, and more native calls for production stations. Everything else is as in 0.2.0-dev.29.16.

**Not all of it checked in a real game yet.** This patch passed Kiln's tests and lab checks on a dedicated server. What a game client shows (crafting counts from station outputs, the launcher's custom game folders) has not been seen in a real game yet. If something looks or works wrong, tell us on GitHub or Discord with `kiln/logs/kiln.log`.

## Players

- **Custom game folders, started without Steam.** The launcher can now play a copy of Enshrouded that no Steam library knows: an older build you keep for mods, a copy on another drive, a backup of the game folder. Add it on Play (**Add** under the game folder) or in Settings → Games. Such a folder starts directly: Kiln runs its `enshrouded.exe` itself (on Linux under umu-run, Proton or Wine), with the same profile, save backup, start progress, crash reports and support report as Steam's copy. The launcher needs no Steam for that: not installed, not running. Kiln never sets `SteamAppId`, never writes `steam_appid.txt` and never touches `steam_api64.dll`; whether a given copy of the game needs Steam to run is that copy's business. Steam's own copy still starts through Steam by default; the choice is per game. Guide: [launcher/custom-game-folders.md](../launcher/custom-game-folders.md).
- **Other mods' slash commands reach their mods.** A chat line starting with `/` that names no Kiln command now passes through untouched to the game and other mods, instead of Kiln answering "Unknown command". A server that wants Kiln's reply back sets `"unknownCommands": "reply"` in `kiln/config/chat.json`.

## Fixed

- **Stutters of about 2 seconds every few minutes when hosting from a hard drive.** About once a minute, kiln-emf wrote its status file on the world's own thread and waited for the disk, even with no EMF mods installed; kiln.spawn did the same when a world was first saved. Both now write on a thread of their own. If their step still takes over 100 ms, kiln.log names the parts that took the time (`slow tick: …`). Thanks to HadToRegister for the logs.
- **EMF mods that ask why breaking blocks is unavailable** get EMF's own "not available on this game version" (Night Raids 1.2.1 compares it; GitHub #43).
- The overlay's crash-guard warning in kiln.log now names the step that failed and the Windows error, and a later successful write says the guard is up to date again.
- A boot snapshot that grows past its size budget keeps working instead of being thrown away.

## Mod authors

- **The mod API is 0.2.9.** Everything new is additive: no public member of 0.2.0-dev.29.16 was removed or changed. Use the 0.2.0-dev.29.17 SDK and MDK.
- **Station outputs as stock (GitHub #68, proposed by bisdat).** `Stations.SetOutputSource(station)` lets a production station lend its finished items (charcoal still in the kiln) to its own base, kept with the save; `IsOutputSource`, `OutputSources(base)`. Opted-in outputs are the last source:
  - of a **fill** (`Stations.Fill`, the station screen): after the player's bag and the Magic chests, inside the game's own all-or-nothing transfer. `FillOptions.UseStationOutputs` (default true), `FillInput.Outputs`, `StationResult.FromOutputs`; row `stations.output_sources`.
  - of a **player's craft**, at any crafting menu: after the bag and the Magic chests, all or nothing, same base only, never a station's queued inputs, leftovers or an output that is also an input, with the game's own base and permission checks. Rows `stations.craft_sources` (server) and `stations.craft_ui` (a Kiln client's counts). A Kiln client's crafting menu counts the outputs it may use; a game without Kiln shows its normal counts and can still craft what its bag and chests cover. The station screen's own fill button still needs the bag and chests to cover a fill before it lights up.
  - Guide: `docs/kiln/services/stations.md`, "Station outputs as crafting stock" and "Station outputs in a craft".
- **Ordinary chests in a fill:** `FillOptions.Chests` names up to 64 storage chests of the station's base, used after the Magic chests and before station outputs, in the order given.
- **Resource patches** (`resourcePatch`, `ResourcePatchBlock`): `copyComponents` copies a component whole from another template, `clear` empties a list, `replace` sets a list's values exactly; with `removeComponents`, `addComponents`, `append` and `set` they apply in a documented order, whole or not at all. Guide: `docs/kiln/modding/resource-patches.md`.
- **Boot reads for any resource:** `names:resources/<qualified type name>` lists every resource of a type, and `resource:` reads one of any type, not only items and templates. The boot snapshot now holds them (about 300 MB; an older snapshot is made again once at the next start through the launcher). Guide: `docs/kiln/modding/boot-gamedata.md`.
- **`kilnctl tick-compare BEFORE AFTER [--json]`** compares two `tick-stats.jsonl` files: per-world step time, steps over budget, and each mod's share (GitHub #57).
- **C and native mods:**
  - kiln.stations: `base_stock_with_stations`, a native `collect` into the base's Magic chests (its own rules: `docs/kiln/services/stations.md`, "Native collect"), named chests on a fill request (`KILN_STATION_REQUEST_V1` 88 bytes, the new request 104 bytes; `submit` takes exactly one of those sizes), `set_output_source` / `output_sources`, the fill flag `KILN_STATION_FILL_NO_OUTPUTS`. Table slots are appended; nothing shipped moved.
  - `kiln_playerstate.h` (holding or cancelling a player's station action) and `kiln_hook.hpp` with the other C++ helpers now ship in the SDK's `native/include`. Example: `docs/kiln/services/player-state.md`.
  - One DLL that runs as a Kiln native mod and, without Kiln, as an `.asi`: the pattern and a C example in `docs/kiln/modding/native-asi.md`. When a package carries both forms of one mod, the launcher places only the Kiln native mod and says so.
  - Permission checks and display names stay managed-only for now (`docs/kiln/services/stations.md`).
- **Not changed:** `Stations.Collect` and `Stations.CollectToBase` behave exactly as in 0.2.0-dev.29.16.

## Checked

Host tests for every part above (Kiln's managed and native suites, the launcher's Rust and TypeScript tests, the ShroudForge fork's tests) and lab runs on a dedicated server: fills and a player character's craft paid partly from a kiln's charcoal while its queued logs stay, ordinary chests, the native calls, resource patches and boot reads, and kiln-emf with and without EMF mods.

A player without Kiln joining a Kiln dedicated server whose mods all say `"clients": "none"` was seen in a real game (MicDrop7). Not yet seen in a real game: a Kiln client's crafting counts from station outputs, a craft paid from them on a hosted game, collecting into a player's bag, the player-state cancel example, and custom game folders started directly.
