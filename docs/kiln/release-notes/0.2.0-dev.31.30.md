# Kiln 0.2.0-dev.31.30

Flamebound Ledger no longer needs its own Kiln host setup: from this release Kiln itself provides the framework for the
checked item moves the Ledger's transfers use. Nothing else changes for players.

## Players and server admins

- **Flamebound Ledger without a host setup.** The Ledger's item transfers between its terminal and your chests needed
  the Ledger's own Kiln host setup, which patched two of Kiln's files and worked only on Kiln 0.2.0-dev.31.22: on 31.23
  to 31.29 it refused to install. From 0.2.0-dev.31.30 Kiln carries the checked moves the Ledger uses, so no host setup
  is needed. Update the Ledger when its new version is out.
- **Where it runs.** Kiln's checked moves run where the world runs: on a dedicated server, so update Kiln there; in a
  hosted game, in the host's Kiln.

## Modders

- No mod API change: mod API 0.2.26, as in 0.2.0-dev.31.29. The MDK packs are 0.2.0-dev.31.30. Kiln.Items has two new
  members, experimental in 31.x (below).
- **Checked moves.** Kiln provides the framework for checked moves, for a mod's own inventory screens and terminals:
  `Items.MoveChecked(from, expected, to, count, destination)` moves `count` items of `expected` (a slot as `Items.Read`
  listed it) only while that slot still holds what the read saw: the item and the count, and for gear the same item
  entity with the same stamp. With `destination` (a slot of `to` from a read), that slot must still hold what it held
  (an empty one: still empty) and takes the whole count, or nothing moves; without it Kiln picks the slot, as for
  `Items.Move`, and a part may move (`Partial`). kiln.items checks both slots inside the move's own inventory
  transaction, in the step the move runs. `SlotChanged`: a slot no longer holds what was read. `NoRoom`: the destination
  cannot take the whole count. Either way nothing moved, in both inventories. A request sent twice moves once. No
  `MoveOptions`: equipped and held items and the action bar are refused, as by `Items.Move` without options.
- **Experimental in 31.x, normal API in 0.2.0-dev.32.** `Items.MoveChecked` and `Items.CheckedMovesAvailable` are
  `[Experimental("KILNX033")]` in 31.x, because a 31.x patch keeps mod API 0.2.26: opt in with
  `<NoWarn>$(NoWarn);KILNX033</NoWarn>` in the project file. In 0.2.0-dev.32 they are normal API, with the same
  signatures, and need no opt-in.
- **Detect them with `Items.CheckedMovesAvailable`.** Ask it before `Items.MoveChecked`: it is false while moves are
  off (a joined client, the kiln_items program not running), and `MoveChecked` is then `Unavailable` with the reason.
  Gear also needs capability `items.instances`. On a Kiln older than 0.2.0-dev.31.30 neither member exists: a mod that
  loads there too looks both up by reflection and takes a missing one as false, as Flamebound Ledger does, or requires
  `"kiln": ">=0.2.0-dev.31.30"` in its manifest's dependencies.
- **Native.** Set `KILN_ITEMS_MOVE_CHECKED` on a STACK move and pass a `KilnItemsCheckedMoveRequest`: the 40-byte
  request, then the source and destination `KilnItemsSlotWitness` (72 bytes). `status2` sets
  `KILN_ITEMS_HAS_CHECKED_MOVE` in `reserved`; an older kiln.items refuses the flag. No function is added to the table,
  and moves without the flag behave as before.
- Guides: [modding/inventory.md](../modding/inventory.md#checked-moves) ("Checked moves"),
  [services/items.md](../services/items.md), and [KILNX033](../modding/analyzers.md#kilnx033).
- Tests: the items host suite's checked moves (`move_test.cpp`: a changed source or destination, a full or occupied
  destination, a destination with room for part of the count, a dry run, a request run twice, gear by item entity and
  stamp, both inventories unchanged after each refusal) and `CheckedMoveTests` (what the call refuses itself, the
  request it hands kiln.items, the test kit's answer).

## Not yet seen in a real game

- Kiln 0.2.0-dev.31.30 has not been in a real game yet, with or without Flamebound Ledger's new version. The same
  checked-move code was in the Ledger's 0.5.1 host setup for Kiln 0.2.0-dev.31.22.
