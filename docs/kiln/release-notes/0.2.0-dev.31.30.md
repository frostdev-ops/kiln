# Kiln 0.2.0-dev.31.30

The Configs window now marks the settings of mods you removed and can clear them, and Flamebound Ledger no longer needs
its own Kiln host setup. For mods, at mod API 0.2.28, Kiln provides the framework for attack speed mods (Kiln.ActionSpeed,
for melee, bow and tool), input mods (Kiln.GameInput), checked item moves and map markers with their own names.

## Players and server admins

- **Removed mods' settings are marked "Not installed".** Remove keeps a mod's settings on purpose, so that adding the
  mod again brings them back. Mods, More, Configs listed those kept files next to your mods' files, with switches that
  looked live. They now sit apart under "Not installed: kept for when you add it back", read-only, with a line saying
  that changes do nothing until the mod is back. A mod you only switched off is still installed: its settings are as
  they were.
- **Clear settings.** Each of those files has a Clear (the bin on its row, or "Clear settings" in its card), and the
  group has "Clear all". Kiln names the files and asks first, then moves them into the settings backups that "Remove its
  settings too" already uses (`backups/mod-settings/config-<profile>-<time>/` in Kiln's data folder), and a message
  says where the copy is. A mod you add again later starts from its defaults.
- **Your installed mods' settings are never touched.** Kiln checks again when you press Clear: if the mod came back
  meanwhile, or Enshrouded is running, nothing is moved. When Kiln cannot tell whose a file is, or cannot read one of
  the places a mod can be, it marks nothing. Kiln's own files, EMF's core settings and Shroudtopia's shared file are
  never marked, and a server's Configs page is unchanged.
- **Flamebound Ledger without a host setup.** The Ledger's item transfers between its terminal and your chests needed
  the Ledger's own Kiln host setup, which patched two of Kiln's files and worked only on Kiln 0.2.0-dev.31.22: on 31.23
  to 31.29 it refused to install. From 0.2.0-dev.31.30 Kiln carries the checked moves the Ledger uses, so no host setup
  is needed. Update the Ledger when its new version is out. Kiln's checked moves run where the world runs: on a
  dedicated server, so update Kiln there; in a hosted game, in the host's Kiln.
- **Mod markers can carry their own names on the map.** Kiln provides the framework for a mod's marker on the world map
  to show its own name in the game's map tooltip ("Golden chest 3"), in the game's own font and style, instead of the
  icon type's name ("Custom marker" for every chest pin). You see this only with a mod that uses it; every other mod
  marker shows what it showed before, and the game's own markers and your own map pins keep their names. The game's
  text filter applies, as to a name a player typed, and Chinese, Japanese and Korean names are drawn with the game's own
  fonts.
- **Mod markers keep their own icons.** When one mod marker came nearer to you than another (a marker that follows a
  creature or a player, for one), two markers with different icons could show each other's icons on the map until the
  map redrew its markers. Each mod marker now keeps its place in the game's map list, and with it its icon.
- **Known issue: a changed icon.** When a mod gives a marker another icon while the number of map markers stays the
  same, an open map can keep the old icon until a marker is added or removed or the map's filter is used. The name in
  the tooltip changes at once. This is older than this release.
- **Named markers on a server.** A server mod can send such markers too. A player gets them when their Kiln is this
  version or newer; a player on an older Kiln does not get those markers at all, unless the server mod also sends them
  a plain one. The server itself needs nothing new: the map is the players'.
- **Attack speed mods.** Kiln.ActionSpeed, for melee, bow and tool, provides the framework for attack speed mods: a mod
  can make a player's melee attacks, bow shots and tool swings faster or slower, from half speed to ten times, and Kiln
  does the game-specific work on clients and dedicated servers. Nothing changes by itself: until a mod sets a value,
  Kiln hooks nothing for it.
- **Speed mods in multiplayer.** With a mod such as Combat And Attack Tweaks on the dedicated server or the host, Kiln
  sends the speeds to every player who runs Kiln, and each player's own swing uses them, so it looks and plays right.
  The mod doesn't need a synced config for this. Players without Kiln, or on an older Kiln, see the server's results
  at the server's timing.
- **Very high speeds.** Values above about 3 to 5 times on busy dedicated servers are untested. Melee hit sampling at
  high speed is not in this release: above 2x a fast melee swing can miss a target between two server ticks.
- **Bows.** A new bow speed applies from the next draw; a draw in progress keeps its time.
- **Input mods.** Kiln.GameInput provides the framework for attack and action input mods: a mod such as Combat And
  Attack Tweaks can turn a held attack into repeated light attacks, or let a fully drawn bow shoot by itself, through
  Kiln instead of its own hooks into the game. Your key bindings and controller work as you set them, and nothing
  happens while a game menu, the inventory, the map, the chat, Kiln's menu or a Kiln window is open, or while the game
  is not the window in front. Kiln does not repeat, press or release anything on its own; only a mod you install does,
  and only on your own character.
- **Input mods in multiplayer.** The presses are your own input and go to the host or server like the rest of it; the
  host or server still decides what happens. Each player's hold-to-repeat setting is their own, and a host or server
  needs no setup for it. A dedicated server does not use it at all.
- **Thanks** to HTR for the report "does Remove really remove?" (it does remove the mod; its settings stay on purpose,
  and now the window says so), to cykel-far for the request and the precise report of what the map tooltip showed
  (kiln#160), and to the Combat And Attack Tweaks author, whose mod and detailed native notes (the game's action timing,
  its input writer and input message) are the base of the action speed and input work, and its first user.

## Modders

- **Mod API 0.2.28 (from 0.2.26). 0.2.27 is the dev.32 beta 1; this release does not contain dev.32's API.** The MDK
  packs are 0.2.0-dev.31.30.
  - The new API: `Kiln.ActionSpeed` in Kiln.Combat (`ActionSpeed`, `ActionSpeedChanged`, `ActionSpeedStatus`),
    `Kiln.GameInput` in Kiln.Client (`GameInput`, `GameAction`, `GameInputSample`, `GameInputHandler`) and `ActionKind`
    in Kiln.Api (shared by both), with the names and signatures of the preview SDK 0.2.0-dev.31.30-preview.1, and
    `Items.MoveChecked` and `Items.CheckedMovesAvailable` (normal API, no opt-in).
  - `ActionKind` moved from Kiln.Combat (where the preview SDK had it) to Kiln.Api, in namespace `Kiln` with the same
    values, so that Kiln.Client and Kiln.Combat need not reference each other. Kiln.Combat forwards it: a mod built
    against the preview SDK still loads, and its source compiles unchanged.
  - Older mods keep working: the API is additive, and nothing was removed or changed.
  - A mod built against 0.2.28 asks for it in its manifest (`apiVersion`, which the SDK writes), and an older Kiln
    refuses it cleanly at load instead of failing later.
- **Checked moves.** Kiln provides the framework for checked moves, for a mod's own inventory screens and terminals:
  `Items.MoveChecked(from, expected, to, count, destination)` moves `count` items of `expected` (a slot as `Items.Read`
  listed it) only while that slot still holds what the read saw: the item and the count, and for gear the same item
  entity with the same stamp. With `destination` (a slot of `to` from a read), that slot must still hold what it held
  (an empty one: still empty) and takes the whole count, or nothing moves; without it Kiln picks the slot, as for
  `Items.Move`, and a part may move (`Partial`). kiln.items checks both slots inside the move's own inventory
  transaction, in the step the move runs. `SlotChanged`: a slot no longer holds what was read. `NoRoom`: the destination
  cannot take the whole count. Either way nothing moved, in both inventories. A request sent twice moves once. No
  `MoveOptions`: equipped and held items and the action bar are refused, as by `Items.Move` without options.
- **Detect them with `Items.CheckedMovesAvailable`.** Ask it before `Items.MoveChecked`: it is false while moves are
  off (a joined client, the kiln_items program not running), and `MoveChecked` is then `Unavailable` with the reason.
  Gear also needs capability `items.instances`. On a Kiln older than 0.2.0-dev.31.30 neither member exists, and a mod
  built against 0.2.28 is refused there at load. A mod that must also load on an older Kiln builds against an older MDK
  and looks both up by reflection, taking a missing one as false, as Flamebound Ledger does.
- **Checked moves, native.** Set `KILN_ITEMS_MOVE_CHECKED` on a STACK move and pass a `KilnItemsCheckedMoveRequest`:
  the 40-byte request, then the source and destination `KilnItemsSlotWitness` (72 bytes). `status2` sets
  `KILN_ITEMS_HAS_CHECKED_MOVE` in `reserved`; an older kiln.items refuses the flag. No function is added to the table,
  and moves without the flag behave as before.
- **Action speed (`Kiln.ActionSpeed`, in Kiln.Combat).** Kiln provides the framework for attack speed mods, for melee,
  bow and tool. Require `"kiln": ">=0.2.0-dev.31.30"`.
  - **The calls.** `ActionSpeed.SetDefault(kind, m)` for every player (also later joins), `Set(player, kind, m)` for
    one player, `ClearDefault`, `Clear(player, kind)`, `Clear(player)`, `Get(player, kind)` (the effective value, any
    side), the `Changed` event, `Available` and `Status`. Kinds: `Melee` (light and heavy attacks, combos, recovery),
    `Bow` (draw, fire and the shot; not staffs or wands), `Tool` (axe, pickaxe and the like).
  - **Rules.** Each mod's values are its own; across mods they multiply, clamped to 0.5 to 10 (`ActionSpeed.Min`,
    `ActionSpeed.Max`). A value outside that range throws. A mod's values go when it unloads, and a player's when they
    leave. Players only in this version. The server or the host sets values on the tick thread; on a joined client the
    setters throw `InvalidOperationException`.
  - **What Kiln scales.** The action's sequence clock (hits, combos, recovery) and its animation together, and for a
    bow the fresh, skill-adjusted charge and fire durations. Kiln classifies the action from its trigger and its item's
    equipment slot type; any other action keeps the game's timing.
  - **Melee hit sampling at high speed is not in this release.** `ActionSpeed.MeleeSamplingAbove` is 2.0, but
    `Status.MeleeSampling` is false (capability `combat.melee_sampling`: "planned: needs an in-game check first"). A mod
    may keep its own contact sampling for now and read the rate with `ActionSpeed.Get(player, ActionKind.Melee)`.
    Kiln's sampler follows in a later release, after an in-game check. Values above about 3 to 5 times on busy
    dedicated servers are untested.
  - **Capabilities.** `combat.action_speed` (sequence and graph), `combat.bow_timing`, `combat.melee_sampling`, and
    `combat.action_speed.prediction` (a game client).
  - **Native.** A new table, `kiln.combat.speed` v1 (`kiln_action_speed.h`, published by kiln-combat.dll). New sigdb
    definitions `combat-speed.json` for client 26430625 and server 26430253, with every site verified statically
    (docs/re/action-speed.md).
- **Game input (`Kiln.GameInput`, in Kiln.Client).** Kiln provides the framework for attack and action input mods: a
  client mod can read the local player's game actions after the game has resolved them, and press or release an action
  for one input step.
  - **The calls.** `GameInput.Available`, `IsHeld(GameAction)`, `WasPressed(GameAction)`, `OnSample(GameInputHandler)`
    and `Repeat(GameAction, TimeSpan interval, Func<bool>? whileHeld = null)`; `GameAction` (`PrimaryAttack`,
    `SecondaryAttack`, `Block`, `Dodge`, `Jump`, `Interact`; append only); `GameInputSample` (a ref struct: `Player`,
    `HeldKind`, `BowFullyDrawn`, `IsHeld`, `Press`, `Release`) and the `GameInputHandler` delegate.
  - **Where it reads and writes.** In the game client's own input writer, once per client world step on the main
    thread, after the game's bindings, controller mapping and menu handling, before the simulation and the input
    message use the record. No keyboard polling. Each `GameAction` is a set of the game's `PlayerInputType` bits;
    `Press` clears the action's derived bits (tap, hold, release) and sets its "down" bits, so a one-step press is a tap
    and never the heavy attack.
  - **Gates.** Handlers and repeats run only with the in-game HUD up (no other game screen, the chat included), without
    Kiln's menu or a capturing Kiln window, and with the game window in front (kiln.ui's screen and status and the
    foreground window, read each client step). Reading is never gated.
  - **Stale presses** are Kiln's: when the game skips its writer for a step, Kiln clears the bits it pressed before the
    input message would send them again (same record, player, session and digital word, a later step). Always on.
  - **`Repeat`**: a press for one step, releases until the interval (at least 50 ms), again, while `whileHeld` (default:
    the action itself is held). It ends when disposed, when its world ends (the world of its first sample) or when the
    mod unloads. **`HeldKind`** comes from Kiln's item catalog and the game's ranged weapon state; **`BowFullyDrawn`**
    is the game's own draw test, with skills and `ActionSpeed` included.
  - **Errors.** `OnSample` and `Repeat` throw `InvalidOperationException` on a dedicated server, where the capability
    row `client.game_input` is off, outside mod code or with 64 subscriptions already; reads never throw (false).
  - **Native.** `kiln.client.game_input` v1 (`kiln_client_game_input.h`: `last`, `subscribe`, `repeat`,
    `unsubscribe`), new sigdb feature `client.game_input_sites` on client 26430625 (with `client.input_observation`),
    and kiln.log says once when it does not resolve. Nothing is hooked until the first use; then two mid links
    (kiln.client's observation of the input writer, now shared with building input, and the guard in the input
    message).
- **Map marker names: no signature or enum change.** `MarkerMapLabel.NativeTooltip` and the `markers.map_text` row were
  already in the API; until now the row was always off and `Markers.Set` with NativeTooltip threw
  `KilnUnavailableException`. `markers.map_text` is now on on a game client when `markers.map` is on and the new client
  sigdb feature `markers.map_tooltip_text` resolves (Steam build 26430625 has it). Where it does not, the row stays off
  with the reason, `Set` keeps throwing `KilnUnavailableException` naming `markers.map_text` (set the marker with
  `MarkerMapLabel.None` then), and kiln.log says once at start "markers: the game's map tooltip cannot be found on this
  build (markers.map_tooltip_text): MapLabel.NativeTooltip is refused (markers.map_text off), map icons keep the game's
  own names".
- **How the game shows `Text`.** As the tooltip's title, through the game's own path for names players type: its text
  filter when it has one, and `<` and `\` escaped, so markup shows as typed. Kiln's text rule applies (at most 128
  bytes of UTF-8, one line). An empty `Text` leaves the icon type's own name. Two icon types name themselves: on
  `tower_locked` (Ancient Spire) the title stays "Ancient Spire" and `Text` is the line under it, and on
  `playerwatersource` (Water Source) the tooltip always says "Water Source". `MarkerMapLabel.None` (the default) leaves
  the tooltip as it was: "Custom marker" for the `icon_*` pins, the type's name or nothing for the others.
- **Named markers from a server.** `Markers.Send` takes `MarkerMapLabel.NativeTooltip` now (it threw before). The marker
  goes to the players whose Kiln offers the tooltip in its marker handshake (their `markers.map_text` on, with a
  verified map); every other player is refused for it (counted in `Refused`; the result is `Partial`, or
  `RequiresClient` when nobody took it), so nothing is drawn partly. For a fallback, send those players the same key
  with `MarkerMapLabel.None` (`Markers.Send(player, ...)`). A dedicated server's own `markers.map_text` row is
  `WrongSide`, as `markers.map`. The marker channel stays v1.
- **The map's slot order.** Kiln's map rows now go into the game's map list in a fixed order (local before received,
  then mod id, generation and key) instead of best first. The game keeps each slot's icon until the number of map
  markers changes, so rows that changed places as the camera or a followed marker moved showed each other's icons.
  Which markers get onto the map when room is short is unchanged (`Priority`, then distance from the camera), and so
  are `VisibilityChanged` and the compass and world surfaces.
- **How the map names work.** Each row of the game's map list has a text field the game fills for a named object (an
  entity's player-given name); the game's name for a map entry takes that field before anything else, and the hover
  tooltip starts from that name. kiln.markers fills it in its own rows only (the record's text in its arena, never
  moved or freed while the game runs, at most 4 MiB in all) and calls or hooks nothing of the game's UI. Rows with
  `MarkerMapLabel.None` hold byte for byte what 0.2.0-dev.31.29 wrote; only their order in the list changed. Static
  analysis of client 26430625 in docs/re/map.md, "The tooltip's name", "The tooltip text" and "The layer keeps a slot's
  icon".
- **Configs: nothing to change in a mod.** The config files a mod writes (`<id>.json` and its `.schema/` snapshot,
  EMF's `emf/<id>.ini`) are read as before.
  - **Whose file it is.** A config file belongs to the mod its schema snapshot names (`mod`: what `Config.Register`
    writes, and what kiln-emf writes for EMF), else, with no snapshot, to `<id>` in `<kind>/<id>.<ext>` of an engine's
    kind. Ids are compared without case. Never a mod's: Kiln's own files (`native.json`, `keybinds.json`, `rules.json`,
    ... and every config that names the mod `kiln`), Shroudtopia's shared `shroudtopia/shroudtopia.json`, EMF's
    `emf/emf_core.ini` and `emf/lua.ini` (the switch of the Lua host Kiln bundles), and a file with no snapshot outside
    an engine's folder: a file of your own at the top of the config folder is never marked or cleared.
  - **"Not installed"** means: not an entry of the profile (on or off), not in the Library (any kind, any version), not
    found in the folder of a game Kiln knows (a mod put there by hand, or a folder Kiln kept at the last start). The
    game folders are read only for a file whose mod neither the profile nor the Library has.
  - **Launcher contract.** `config_list` gives each file an `orphaned` flag: only for a profile, false for a server or a
    game and for a file whose mod is not known; callers that do not know it ignore it. `config_clear_orphans(target,
    files)` is new, for a profile only. It checks every file again and refuses the whole request, touching nothing: an
    installed mod's file, a file that is nobody's or a place it could not read (`conflict`), a running game
    (`game_running`), a missing file (`not_found`), a name outside the config folder (`invalid_argument`). A file that
    cannot be removed keeps its snapshot and stays marked. kiln-manage has `config_orphans::{list_profile, owner_of,
    mark, Installed}` and `mod_settings::clear_orphans`; [contracts.md](../launcher/contracts.md) and
    [app.md](../launcher/app.md) (Configs) have the rules.
  - **The backups.** `<data>/backups/mod-settings/config-<profile>-<time>/` holds `profiles/<pid>/config/...` and a
    `removed.json` `{format, kind: "config", id: <profile>, removed, mods: [ids], items: [{from, backup}]}`: the layout
    and record of Remove's settings removal, with `kind` `config` and the mods' ids in `mods`.
- **Missing API? Request it.** The kiln-modding skill now tells modding agents to help the user request a missing API
  instead of building a workaround: a GitHub issue at https://github.com/frostdev-ops/kiln/issues, or a post in the Kiln
  Discord's #mod-dev, saying what the mod is trying to do and the call it would like to make.

## Not yet seen in a real game

- **Checked moves.** Kiln 0.2.0-dev.31.30 has not been in a real game yet, with or without Flamebound Ledger's new
  version. The same checked-move code was in the Ledger's 0.5.1 host setup for Kiln 0.2.0-dev.31.22.
- **Configs.** Nobody has opened Configs on a real profile with removed mods, or pressed Clear, with this build yet. It
  is tested on temp folders and on the launcher's browser mock; the launcher's own window was not run. A mod that
  something other than Kiln put where Kiln does not look is not seen, so its file would be marked; Clear always keeps a
  copy in the backups.
- **The new launcher texts** are in all eleven launcher languages; the ten translations are machine translations that
  no native speaker has read yet.
- **The map tooltip.** Nobody has hovered a marker with this build yet. It rests on static analysis of client 26430625
  and host tests; cykel-far offered to test a dev build in single player. Chinese, Japanese and Korean names in the
  tooltip of an English game were not watched (the game's default font group carries Noto Serif SC and KR for them).
- **The map icons.** Mod markers keeping their icons as they move past each other rests on the same static analysis.
- **Mixed servers.** A server's NativeTooltip markers on a dedicated server with players on this and on older Kiln
  versions.
- **Action speed** at all: host tests over fakes, static checks on both exes and managed tests only. A guest applying
  the server's speeds to its own swing (it relies on the same entity id in its prediction and client worlds as on the
  server), the graph scaling's look while a player attacks on the move (the whole animation takes the rate), and the
  cost on a busy dedicated server at high speeds were not watched.
- **Game input.** Nobody has held an attack or drawn a bow with this build yet. It rests on static analysis of client
  26430625, host tests and C# tests. On a joined client, `BowFullyDrawn` compares the host's replicated draw start with
  the client world's clock (as Combat And Attack Tweaks does today); that they line up was not watched. Which press
  pattern the game turns into a light attack is the Combat And Attack Tweaks author's (the old Hold To Light Attack
  mod's); Kiln did not trace the server side of it.
