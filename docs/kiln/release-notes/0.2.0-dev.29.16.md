# Kiln 0.2.0-dev.29.16

Kiln's in-game menus in the game's own look, Kiln in your language, the launcher's icon on Linux taskbars, faster starts on hard drives, and a new SDK (mod API 0.2.8) with themes for mods' windows. Everything else is as in 0.2.0-dev.29.15.

**Not yet checked in a real game.** This patch passed Kiln's tests and lab checks on a dedicated server, but what a game client draws (the new look, translations, icons) has only been checked in Kiln's own preview renderer, not in the game. If something looks or works wrong, tell us on GitHub or Discord with `kiln/logs/kiln.log`.

## Players

- **Kiln's menus look like the game.** Kiln's own windows (the Kiln menu, Keys, the creative menu, item details, notifications, the radial wheel) now use the game's colours and font, read from your game, instead of Kiln's red and black. Pick another look under Mods → Kiln settings → Look, or in the launcher's Settings: the game look (default), a translucent game look, Kiln's classic look, or a theme a mod offers, plus the overlay's opacity and size. Changes show at once.
- **Kiln in your language.** The launcher and Kiln's in-game menus can now be translated. The launcher's Settings → Language picks the launcher's language (System by default) and Kiln's in-game language (by default the game's). Chinese, Japanese and Korean use the game's own fonts. English is the only language shipped so far; Simplified Chinese is being translated by XHL. Want to help with another? See [translating.md](../translating.md).
- **The launcher's icon on Linux taskbars and menus.** The AppImage now adds its own app-menu entry and icons in your home folder (Settings → Appearance → "Kiln Launcher in the app menu" removes them), so Hyprland, GNOME and other desktops show Kiln's icon. On Windows the launcher and its pinned shortcut share one taskbar button, and `kilnctl.exe` and `kiln.exe` carry Kiln's icon.
- **Chat history, by bisdat.** In the game's chat (the HUD's and the Social page's), Up and Down bring back what you sent before, and Down past the newest brings back the line you hadn't sent yet. Slash commands are kept across restarts; ordinary chat only for the session, and nothing that looks like a password, key or token is kept. Off by default: switch it on in the launcher's Settings or with `"ui": {"chatHistory": true}` in kiln.json. Tested in the game by bisdat ([pull request 63](https://github.com/frostdev-ops/kiln/pull/63), GitHub #44). Thanks, bisdat!
- **Kiln's mark is back in the main menu**, before its line at the bottom (missing since 0.2.0-dev.29.15).

## Fixed

- **Long freezes at start on hard drives.** On a PC whose game and Windows are on hard disks, Kiln could freeze the loading screen for several seconds: its check for another mod loader read every newly loaded DLL whole, including several hundred megabytes of graphics-driver files, on the game's own thread. That check no longer reads anything in the Windows folder and runs on its own thread; Kiln's overlay writes its small files off the game's thread; the Shroudtopia loader stops re-reading mod DLLs every half second; Kiln.Saves' backup pruning reads only files that changed; and Kiln reads mods' files ahead while the game starts. Thanks to HadToRegister for the performance recording.
- **ShroudForge no longer rebuilds its asset mods at every start.** With a ShroudForge asset mod that also exports a file (Holster Toggle, for one), every start restored the game's data and applied all asset mods again: over two minutes on a Steam Deck. ShroudForge now keeps a record beside its backup (`enshrouded.kfc.prepared.json`) and skips that step while the mods, the game build, the game's data files and the exported files are as the last start left them; any change, or anything it cannot check, applies them again. It also applies them again when another program replaced the game's data file, where it used to skip.
- **Less disk writing while you play with ShroudForge.** Its status file was rewritten and forced to disk about 1.5 times a second; now every 3 seconds, the diagnostics part only when it changes.
- **Linux: configs edited in the launcher stay.** With a Flatpak or Snap Steam (or a Wine prefix without Z:), a value set in the launcher's Configs page was replaced by the game's older copy at the next start or mod update (for example Kiln Auto Loot's stack size). The launcher now copies back only what the game changed; when both sides changed, the newer wins and the other is kept as `<name>.conflict-<time>` with a warning. The first start after this update may leave such a file where the two copies already differed.
- **A config Kiln cannot read at start is never reset.** If a mod's config file was locked or unreadable when Kiln started, Kiln wrote the mod's defaults over it. Now it leaves the file alone and reads it again.
- **Mods that only partly run under Kiln say so.** Some mods ship a modified EML loader (`dbghelp.dll`) with code of their own, such as Put Away Your Weapon's holster hotkey. Kiln runs their EML part but not that DLL, and the launcher used to call it "not needed". It now marks such a mod "Only partly runs" and says what doesn't run, as do kiln.log and the support report.
- A server step no longer scans every entity for players (kiln-skills), which cost noticeable server time in big worlds.

## Mod authors

- **The mod API is 0.2.8.** Everything new is additive: no public member of 0.2.0-dev.29.15 was removed or changed. Use the 0.2.0-dev.29.16 SDK and MDK.
- **Looks and themes** (Kiln.Ui): `UiStyle.Player` (the look the player chose) is now the default for `Ui.Window`, `Ui.Screen` and crafting panels; before, windows defaulted to Kiln's ember look. `ui.Palette` reads the look's colours by role. `Ui.Themes.Define(name, UiThemeSpec)` defines a theme (colours by role, spacing, rounding, background opacity, a font) for your own windows (`Theme =` on their options, or `using (ui.Theme(theme))`), and `OfferToPlayer` lets the player pick it for all of Kiln's UI; a mod never restyles other windows by itself. `Ui.LoadFont` and `ui.ModFont` give your windows a font of their own. Guide: `docs/kiln/ui.md`.
- **Trimmed icons and parts of images:** `UiDraw.ItemIconTrimmed`, `ImageTrimmed`, `ImagePart`, `ImageButtonTrimmed`, `RenderDraw.ImageTrimmed` and `RenderDraw.ImagePart` draw an item icon or image without its transparent margins, or a part of an image. The existing calls draw as before.
- **`Assets.ReadResidentBlob(ContentHash)`** reads a blob from any thread without asking the game for its content index (null until the blob is resident; `AssetsCatalogChangedEvent` `Ready` says when). Guide: `docs/kiln/services/assets.md`.
- kiln.log's line for each code mod now splits its load time: `loaded in T ms (layout check A ms, assemblies B ms, OnLoad C ms)`.
- A mod that lists `Stations` (not `Blocks`) in `KilnServices` no longer gets a false KILN108 for `BaseIdChange`.
- **C:** the kiln.ui table grows to 1016 bytes: theme, look and font slots, `image_ex` and `image_opaque_rect`, and `set_texts` (Kiln's own; refused from native plugins). Guide: `docs/kiln/services/ui.md`.

## Translators

The launcher's texts are in `launcher/src/i18n/en.json`, Kiln's in-game texts in `runtime/locales/en.json`. Translate them into `<language>.json` next to them (for example `zh-CN.json`) and send a pull request or the files; you are credited in CREDITS.md. Guides: [translating.md](../translating.md) and [translating-game.md](../translating-game.md).

## Checked

Host tests for every part above (Kiln's managed and native suites, the launcher's Rust and TypeScript tests, the translation checks, the ShroudForge fork's tests) and a lab run on a dedicated server. The look, the translations, the CJK fonts and the overlay were rendered with Kiln's preview tool using the game's real colours and fonts.

Chat history was tested in the game by bisdat.
