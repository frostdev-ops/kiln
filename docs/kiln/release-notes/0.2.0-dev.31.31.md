# Kiln 0.2.0-dev.31.31

The Configs window no longer shows the settings of mods you removed as if they were live: it marks them "Not
installed", read-only, and lets you clear them into Kiln's settings backups.

## Players and server admins

- **Removed mods' settings are marked "Not installed".** Remove keeps a mod's settings on purpose, so that adding the
  mod again brings them back. Mods, More, Configs listed those kept files next to your mods' files, with switches that
  looked live. They now sit apart under "Not installed: kept for when you add it back", read-only, with a line saying
  that changes do nothing until the mod is back. A mod you only switched off is still installed: its settings are as
  they were.
- **Clear settings.** Each of those files has a Clear (the bin on its row, or "Clear settings" in its card), and the
  group has "Clear all". Kiln names the files and asks first, then moves them into the settings backups that "Remove its
  settings too" already uses (`backups/mod-settings/config-<profile>-<time>/` in Kiln's data folder), and a message
  says where the copy is. A mod you add again later starts from its defaults.
- **Your installed mods' settings are never touched.** Kiln checks again when you press Clear: if the mod came back
  meanwhile, or Enshrouded is running, nothing is moved. When Kiln cannot tell whose a file is, or cannot read one of
  the places a mod can be, it marks nothing. Kiln's own files, EMF's core settings and Shroudtopia's shared file are
  never marked, and a server's Configs page is unchanged.
- **Thanks** to HTR for the report: "does Remove really remove?" It does remove the mod; its settings stay on purpose,
  and now the window says so.

## Modders

- No mod API change: mod API 0.2.26, as in 0.2.0-dev.31.30. The MDK packs are 0.2.0-dev.31.31. Nothing to change in a
  mod: the config files a mod writes (`<id>.json` and its `.schema/` snapshot, EMF's `emf/<id>.ini`) are read as before.
- **Whose file it is.** A config file belongs to the mod its schema snapshot names (`mod`: what `Config.Register`
  writes, and what kiln-emf writes for EMF), else, with no snapshot, to `<id>` in `<kind>/<id>.<ext>` of an engine's
  kind. Ids are compared without case. Never a mod's: Kiln's own files (`native.json`, `keybinds.json`, `rules.json`,
  ... and every config that names the mod `kiln`), Shroudtopia's shared `shroudtopia/shroudtopia.json`, EMF's
  `emf/emf_core.ini` and `emf/lua.ini` (the switch of the Lua host Kiln bundles), and a file with no snapshot outside an
  engine's folder: a file of your own at the top of the config folder is never marked or cleared.
- **"Not installed"** means: not an entry of the profile (on or off), not in the Library (any kind, any version), not
  found in the folder of a game Kiln knows (a mod put there by hand, or a folder Kiln kept at the last start). The game
  folders are read only for a file whose mod neither the profile nor the Library has.
- **Launcher contract.** `config_list` gives each file an `orphaned` flag: only for a profile, false for a server or a
  game and for a file whose mod is not known; callers that do not know it ignore it. `config_clear_orphans(target,
  files)` is new, for a profile only. It checks every file again and refuses the whole request, touching nothing: an
  installed mod's file, a file that is nobody's or a place it could not read (`conflict`), a running game
  (`game_running`), a missing file (`not_found`), a name outside the config folder (`invalid_argument`). A file that
  cannot be removed keeps its snapshot and stays marked. kiln-manage has `config_orphans::{list_profile, owner_of, mark,
  Installed}` and `mod_settings::clear_orphans`; [contracts.md](../launcher/contracts.md) and
  [app.md](../launcher/app.md) (Configs) have the rules.
- **The backups.** `<data>/backups/mod-settings/config-<profile>-<time>/` holds `profiles/<pid>/config/...` and a
  `removed.json` `{format, kind: "config", id: <profile>, removed, mods: [ids], items: [{from, backup}]}`: the layout
  and record of Remove's settings removal, with `kind` `config` and the mods' ids in `mods`.
- Tests: kiln-manage's `tests/config_orphans.rs` and unit tests (every mod kind; switched off, in the Library or in a
  game folder is installed; Kiln's and EMF's own files; a profile or a game's `profile.json` that cannot be read marks
  nothing; game folders read only while a mod is missing; Clear's backups and refusals; a file that cannot be removed),
  the launcher's log line, the window's groups and read-only controls (`unit/config-orphans.test.tsx`), and a Playwright
  spec on the mock (`tests/config-orphans.spec.ts`, also at the Deck's 1280x800).

## Not yet seen in a real game

- Nobody has opened Configs on a real profile with removed mods, or pressed Clear, with this build yet. It is tested on
  temp folders and on the launcher's browser mock; the launcher's own window was not run.
- A mod that something other than Kiln put where Kiln does not look is not seen, so its file would be marked. Clear
  always keeps a copy in the backups.
- The new texts are in all eleven launcher languages; the ten translations are machine translations that no native
  speaker has read yet.
