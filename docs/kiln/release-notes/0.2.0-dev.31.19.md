# Kiln 0.2.0-dev.31.19

## Players and server admins

- **Happy Thanksgiving:** over Thanksgiving weekend (Thursday to Sunday, in your local time), a turkey roasts over the launcher's fire. With Animated fire off, or on any other day, the launcher looks as always.
- **Big registry packs hitch much less after the world loads.** After a later change by another mod or loader, a data pack reload or a registry transaction, Kiln now writes `state/registry.json` on a thread of its own instead of on the game's tick. In a host test with 10,000 changed fields, the tick's share of writing the report fell from about 200-275 ms to about 9-14 ms. The registry's own rebuild still runs on the tick.
- `registry.json` is still written when the server stops right after such a change (Kiln waits up to 2 s at exit), and a name that is not valid UTF-8 no longer stops it from being written: the bad bytes show as the replacement character.
- **A quieter kiln.log.** A start with registry content no longer fills kiln.log with tens of thousands of `registry: ... is not read on this build` lines (31.18 wrote 34,207 at each such start). Each field that some items have no value in is now one line, with the count and the first item.
- **What a ShroudForge mod tells you now shows in game.** A ShroudForge mod cannot draw on the game's screen, so it sends its messages to ShroudForge's news feed, which ShroudForge's own window shows. When Kiln runs ShroudForge, there is no such window, and Kiln showed none of those messages. Now each new message pops up over the game as a Kiln message for 10 seconds, at most three at once; a long one is shortened there. The newest three also stay in that mod's details, in full, on Kiln's ShroudForge page (F9). When a mod opens ShroudForge's window (Altar Cleanup's "Open ShroudForge when done"), Kiln's page opens on that mod. For a mod with shortcuts, the page also says that its keys work once the menu is closed. Thanks to netjunk for the report on Altar Cleanup's "Ask before cleaning up": the first press scanned, but its result and "press the cleanup key again within 60 seconds" showed nowhere.
- **The server Map page fits the window.** On a server's World > Map in the launcher, the map fills the page at every window size, including the Steam Deck's 1280×800 and the smallest 1024×640, and stays the same height on Markers, Find & filter and Live. The side panel, the search results and the "no map art" banner scroll inside the map instead of being cut off.
- **Dialogs and menus over the server map take clicks again.** A confirmation, menu or toast opened over the map (Delete waypoint, for example) could not be clicked where it covered the map, because the map's own layers sat above it. Both map fixes were found while testing Kilnwarden.
- **Open web panel goes to your panel's own address.** With Kilnwarden 0.1.4 and hosted access on (`https://<name>.kiln.nexus`, or your own address), a server's Open web panel opens the panel there, signed in, after a quick check (at most 4 s) that the address really is your panel. The status says so, with "Open on this computer instead" beside it. When the check fails, the panel opens on this computer as before and the status says why ("didn't answer in time", "isn't ready for the launcher's sign-in"). With an older Kilnwarden, nothing changes.

## Modders

- No mod API change: mod API 0.2.25, as in 0.2.0-dev.31.18. The MDK packs are 0.2.0-dev.31.19.
- kiln.registry's report (`report_json`) is always the newest report, even just before `state/registry.json` is written: read it there rather than from the file right after a ready event. The file follows within the writer's run (about 0.35 s at 40,000 fields), and its `written` is the time the report was made. kiln.content now sets `KilnPluginInfo.on_unload` for the exit flush.
- A refused live enum value names the Kiln field (`"legendary" is not a value of items.rarity on this game build`), not the game's name of the value.
- To see every entry a field has no value in, and why, set `"log_level": "debug"` in `kiln/kiln.json`: kiln.log then has one `registry: items.manaCost of game:<item>: <reason>` line per entry.
- `shroudforge.notifications.publish` under hosted ShroudForge: Kiln.Ui reads the notices from the runtime's `state.json` `events` section (ShroudForge's `paths.state` folder), where the runtime stores them. It toasts each notice that is new or published again during this game, as long as Kiln answers ShroudForge's menu (no ShroudForge window running). At most 3 notice toasts are on screen at once, newest first; a notice that finds no room shows only in the mod's details. A toast is plain text (line breaks, tabs and control characters become spaces) in at most 4 lines of 96 columns. Entries with neither a title nor a message (ShroudForge's own install and update records) are not shown. The notice's level picks the toast's look: `error` is Error, `info` is Info. ShroudForge's API also names `success`, `warning` and `update`, but its event schema refuses them (fork pin 6cf01443), so such a publish fails in ShroudForge itself. Kiln writes nothing to ShroudForge's folders. It opens `state.json` only when the file changed, briefly and with delete sharing, to stay out of the way of ShroudForge's writes. Kiln's interpreter (kiln backend) keeps its own notices and is unchanged.
- `shroudforge.ui.toggle_modloader()` under hosted ShroudForge still toggles Kiln's ShroudForge page like F9. When it opens the page, Kiln chooses the mod whose notice came within the last 3 seconds. It reads the notices again for up to 1.6 s, since a mod may publish just after it asks.
- Key presses still don't reach ShroudForge while Kiln's menu has the keyboard (0.2.0-dev.31.18). ShroudForge's own runtime counts none while its window is in front either.
- `@kiln/admin-ui`: `configureAdmin`'s host gains `useMapNoArt(art)`, returning `AdminMapNoArt {title | null, body?, action?, markers?}`, so a host words the Map page while it has no map art (the banner's box has the class `ka-map-noart`). `.ka-map-root` is a stacking context of its own (`isolation: isolate`), so the map's layers (z-index 400 to 1200) stay below a host's dialogs and toasts on the body.
- Launcher: `admin_open_web_panel` takes `route` (`auto`, the default, or `local`), and `WebPanelInfo` gains `via: 'hosted'`, `public` and `fallback` (`unreachable` or `refused`). `auto` uses `launcher-endpoint.json`'s `public` + `publicSha256` (Kilnwarden 0.1.4) when a pinned check of at most 4 s passes (the certificate `publicSha256` names, `GET /api/auth/status` with `ownerExists` and `launcherLogin`), and sends the one-time login there through a one-use bootstrap address; no gateway is started for it (contracts.md, admin-protocol.md).
- Launcher: the Thanksgiving turkey is date-gated in `shell/thanksgiving.ts`; in the browser mock `?turkey=1` / `?turkey=0` force it, and a browser under automation (`navigator.webdriver`) leaves it off unless asked. Every other day the fire's shader is the same as in 0.2.0-dev.31.18. A driver that cannot build the turkey's shader keeps every day's fire, without the greeting.

## Not yet seen in a real game

- The turkey in the desktop launcher (WebView2 on Windows, WebKitGTK on Linux and the Steam Deck) and its cost on a weak GPU; it was seen in the browser mock.
- The toast and the page's news for Altar Cleanup's scan result in netjunk's hosted world. Whether Altar Cleanup publishes its "press the key again" question as a notice, rather than only logging it, comes from its Nexus page, not from its Lua.
- `registry.json` written off the tick, and the per-field "has no value" notes, at a game client's start with registry content and on a Windows server (both seen on Linux lab servers only).
- Open web panel at a real hosted address from the desktop launcher, with Kilnwarden 0.1.4.
