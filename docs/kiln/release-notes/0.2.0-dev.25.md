# Kiln 0.2.0-dev.25

A hotfix for 0.2.0-dev.24: ShroudForge mods and EML mods together, XHL mods, and a launcher window that stayed black on some Linux machines.

## Players and server owners

- **ShroudForge's data mods apply again next to EML mods.** 0.2.0-dev.24 made EML mods run when a ShroudForge mod is on. With More Gliders and Unlock Blueprints together, ShroudForge then refused one write of Unlock Blueprints and threw away its whole startup pass, so no data mod applied at all (Crafting Essentials, Unlock Blueprints, More Gliders and the other EML mods). @SF_FIX@
- **XHL mods import again.** XHL's mods since November carry a `mod.json` that only names the mod. Kiln took that file for a broken EML mod, left the mod out and said "Nothing to add". Such a folder is now an XHL-Core plugin, placed in the game's `mods` folder with every file it came with, where XHL-Core loads it. A hand-installed XHL mod in the game folder is shown as an XHL plugin instead of "Can't run".
- **XHL-Core 2.x is recognised.** The launcher said XHL-Core was missing while it was installed, and every download of it became one more mod. It is now one mod, "xhl-core", whose next version replaces it.
- **A black launcher window on Linux.** On some machines (one report: NVIDIA, X11) the launcher's window stayed black. @RENDER_FIX@
- **Update the Kiln runtime in your game too** (the launcher shows the update next to Kiln on Play, or on the Runtime page). The runtime brings the ShroudForge fix.

## Known limits

- XHL-Core adds "XHL Mod Settings" to the game's menu by patching the menu's code. With ShroudForge's mods on, ShroudForge patches the same menu, and XHL-Core may leave its menu entry out while its mods still work. Not checked in a game yet; XHL-Core's own log (`XHL-Native-Plugin-Host.log`) says whether it installed its menu.
- @SF_LIMITS@
- Everything in 0.2.0-dev.24's known limits still applies.
