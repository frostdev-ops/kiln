# Kiln 0.2.0-dev.31.24

A ShroudForge mod that Kiln also counted as an EML mod, such as Mineral Production Boxes, is now one row under ShroudForge in the Kiln menu, and its switch and settings change the copy of the mod that ShroudForge runs. Chinese, Japanese and Korean text in mods no longer shows as `????`.

## Players and server admins

- **One row under ShroudForge, with its switch and settings.** Mineral Production Boxes (Nexus 347) showed up twice in the Kiln menu (Insert, Mods): once under EML with only "Loaded", and once under ShroudForge. The same happened to EML mods that need ShroudForge's runtime, such as Endless Chests and Quiver & Spellbook. For these, Kiln's launcher gives ShroudForge a second entry in the game's copy of your profile. Each of these mods is now one row under ShroudForge, showing what ShroudForge says about it. This works when Kiln runs ShroudForge for you, when your own ShroudForge install runs it, and with Kiln's own ShroudForge interpreter, before and after a save loads. Plain EML mods stay under EML. If Kiln's EML loader fails to apply such a mod, its EML row with the error stays as well.
- **The settings you change are the ones ShroudForge uses.** Up to 0.2.0-dev.31.23, the ShroudForge row of an EML mod that needs ShroudForge's runtime (Mineral Production Boxes among them) showed and changed the mod's copy in Kiln's Library, which ShroudForge never runs. Changes made there did nothing, and labels you edited in the game's mods folder did not show. The row now uses the copy ShroudForge runs: Kiln's copy in the game's mods folder, or your own folder of the mod. Kiln's in-game menu no longer changes files in the Library.
- **If the launcher says the mod "was changed in its folder".** If you changed the settings of such a mod in Kiln's menu with 0.2.0-dev.31.23 or earlier, those changes went into its Library copy. The launcher notices this only when it copies the mod again, for example after its folder in the game's mods folder was removed, or on a Steam Deck in Copy mode. To fix it, close the game, then:
  - press **Use the changed files** to keep the mod with those changes, or
  - add the mod's original zip again with **Add mods** to put its original files back (Kiln keeps the changed ones aside).

  Then make your settings again in the Kiln menu.
- **When only EML runs such a mod, the menu says so.** If no ShroudForge runs it (Kiln's EML loader alone, or EML's own loader in the game folder), the mod stays under EML. Its row then says that its ShroudForge settings do nothing in that start.
- **When your own ShroudForge runs a mod and Kiln cannot read its settings file,** the row points you to ShroudForge's own Modloader window.
- **Chinese, Japanese and Korean text in mods no longer shows as `????`.** Mineral Production Boxes names its resources and settings in Chinese with the English name after it ("矿石 | 铜矿 / Copper Ore"). Kiln's menu only had Latin letters, so in an English game those labels, group titles and hints were all `?`. Now, the first time Kiln is asked to draw such text, it loads the game's own Chinese font, the one the game uses when it is set to Chinese. That font also has Japanese kana, in Chinese letter shapes, and the game's Korean font comes with it. The text can show `?` for a moment until the font is loaded. Nothing is downloaded. The fonts use about 19 MB of memory until you quit, the same as playing with the game set to Chinese. ShroudForge's own Modloader window draws text with its own fonts, so this does not change it.
- **Thanks to HTR** for the report, the screenshots and the tests with his own files.

## Modders

- No mod API change: mod API 0.2.26, as in 0.2.0-dev.31.23. The MDK packs are 0.2.0-dev.31.24.
- **The Kiln menu's ShroudForge group** (`ModCatalog`, `SfiCatalog`). The Library keeps each mod's kind, and kiln-eml and the interpreter's plan treat these mods as before. Only the menu changed:
  - **The launcher's `emlRuntime` compatibility entry.** This is a `shroudforge` entry with the same id and path as the profile's EML entry, which is the package's Library folder. Its row is now the folder ShroudForge runs: Kiln's EML copy in ShroudForge's mods folder, found by its `.kiln-library.json` marker of kind `eml`, or the folder kiln-eml's report names for the package. Only when neither exists does the row keep the entry's path. An EML row whose folder is that entry's path or its row's folder goes, so the ShroudForge row stands for the mod. A failed or missing EML row stays.
  - **A package that is ShroudForge's by its `extended.mod.json`** (`ModCatalog.IsSfOwned`): either it has no `"launcher": "EML"`, or it says EML but has a non-empty `settings`, `groups`, `links` or `changelog`. Its EML row becomes a ShroudForge row while ShroudForge runs (or was to run) ShroudForge's mods folder, and the row then shows ShroudForge's runtime state.
  - **In a kiln-backend start,** the row moves before the interpreter reports, where its record names the package, and while ShroudForge's own loader runs the folder.
  - **A moved row keeps kiln-eml's words** while ShroudForge or the interpreter has none of its own: the profile has the mod off, or it runs although it is off in the profile.
  - **ShroudForge's bare stamp is not ShroudForge's.** The stamp is `$schema`, `schemaVersion`, `enabled`, `targets`, `"launcher": "EML"` and an empty `settings`. It, and Kiln's own switch in its EML copies, never make a package ShroudForge's, so real EML mods never move.
  - **"Its ShroudForge settings do nothing"** shows only on EML rows that kiln-eml or EML's own loader runs, never on a row kiln-eml says ShroudForge runs.
- **The ShroudForge page never writes into Kiln's Library.** A folder with an import record `<folder>.json` beside it (`<library>/<kind>/<id>/<version>+<hash8>`) shows a line saying why instead of its switch and settings, and the page's writer refuses it.
- **If your ShroudForge mod is meant to run only under ShroudForge,** leave `"launcher"` out of your `extended.mod.json` or set it to `"SF"`. Kiln's launcher then imports it as a ShroudForge mod. `"launcher": "EML"` tells ShroudForge and Kiln that the package is an EML mod.
- **CJK text in kiln.ui.** kiln-ui.dll checks the text it is given to draw: labels, texts, combo items and text field values of any `Ui` call, and the render service's text. At the first Chinese, Japanese or Korean character, it merges the game's zh-CN font group into the overlay's fonts for the rest of the process. Kiln's language and the game's language still pick their own group first (`native/services/ui/text_glyphs.h`, `font_group.h` `wanted`; docs/kiln/translating-game.md). kiln.log says `ui: a text in Chinese, Japanese or Korean is drawn (a mod's) ...` once. A font that cannot be read is one kiln.log warning, and the text stays `?`.

## Not yet seen in a real game

- None of this has run with Mineral Production Boxes in a game. HTR's setup (installed with Add mods, his own ShroudForge install, the Library copy with Chinese labels and his English copy in the game's mods folder) is covered by tests over fake state files and folders.
- The Chinese font joining in a real English game. Host tests load it from a fake game resource with a system font, and the same loading path already runs for players who play in Chinese.
- **F9 is unchanged.** With your own ShroudForge install, ShroudForge reads its key through its own helper program, so Kiln's key bindings do not take F9 from it. When Kiln runs ShroudForge for you, F9 opens Kiln's ShroudForge page, and Kiln Auto Loot's default key is also F9: one press does both. Change one of them in Kiln's Keys page.
