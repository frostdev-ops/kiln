# Kiln 0.2.0-dev.24

Fixes from players' reports on a Steam Deck and on Linux, and a review of what 0.2.0-dev.23 shipped.

## Players and server owners

- **Adding mods on a Steam Deck works again.** With ShroudForge installed under Proton, the launcher read ShroudForge's mods folder as `//?/S:/steamapps/common/Enshrouded/mods` and every mod added to a profile failed with "Read-only file system". ShroudForge stores that folder as a Windows path on a drive of the Proton prefix (`S:` on a Deck); the launcher now finds it through the game folder.
- **The in-game Mods page is no longer empty next to ReShade or another overlay.** When another program hooks the game's graphics functions right after Kiln, Kiln could miss the creation of the game's graphics device. Its overlay then drew nothing: the Mods page and every Kiln menu were empty, with no message. Kiln now takes the device over when the game makes its swapchain, if the PC has one graphics device. When it cannot, kiln.log says why, and the support report has the finding "Kiln could not draw in the game".
- **The profile's "Add from the library" list says what it lists.** It shows one kind of mod. With mods of other kinds only it said "The library is empty", which read like a broken Library. It now says "No Kiln mods in the library" (or the kind of the tab) and where the other kinds are added. The Mods tab's list also refreshes when it opens.
- **A game without a window still counts as running.** If the game's window thread ends while the rest of the process goes on (it still hosts and saves the world), the launcher took the game for stopped and wrote the profile into the folder of a running game. It now sees that the game runs. Stop it in Steam before you start it again.
- **Enshwick packs import.** A data pack written like Enshwick's own examples (`authors = ["You"]`, `exports = [...]`, `[[setting]]`, `[[point]]` in `pack.toml`) was refused as "its pack.toml is invalid". Such files are read now.
- **shroudlink mods have one name.** A single mod's zip was imported as `chestsort.dll`, the same mod from the bundle as `chestsort`. Both are `chestsort` now. An entry made by 0.2.0-dev.22 or dev.23 keeps its old name and still works; the in-game list no longer shows it as one more row.
- **The shroudlink card says where its mods run**: in your own game when you play alone or host, and on a dedicated server. Nothing has to be set up.
- **Removing a mod without typing its name.** Settings has "Type a mod's name to remove it". Turn it off and the Library's Remove dialog is one click. Uninstalling Kiln, deleting a profile or a server and restoring a backup still ask for the word.
- One refresh of the active profile at a time: a save and the launcher's watcher no longer write the same change twice.

## Checked, not changed

- Enshwick 1.0.0-alpha.14 (bundled since dev.23) starts under Kiln's host tests with its real loader. Its new rule is read from the source only: Enshwick no longer hooks a function another program hooked first. On the client Kiln is first, so a feature of Enshwick that needs such a function may be off, and its log then names a Kiln DLL. This was not measured in a game.

## Known limits

- Nothing here ran on Windows, on a Steam Deck or in a real client. The Deck fixes follow one player's support report.
- The graphics device takeover needs a second program hooking Vulkan next to Kiln, which no test here has. With more than one graphics device Kiln still cannot draw in that case; kiln.log says so.
