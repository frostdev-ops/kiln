# What a mod cannot do yet

Read this before you spend a day on something that has no API. Each row says what is missing, what stands in the way
(in the game or in Kiln), what to do meanwhile if the tree has an honest workaround, and the release it is planned for.

Checked against the full dev.26 development tree on 2026-11-12: 0.2.0-dev.25 plus every dev.26 package (identity,
api-gate, typegen, hygiene, proof, testkit, core, instances, player-anim, weapon-moves, data-folder). dev.26 is not
released, and **nothing of dev.26 has run in a real client**; rows that name dev.26 work say so. The planned releases are named dev.26, dev.27, dev.28 and dev.29,
then the API freeze at **1.0.0**. A planned release is a plan, not a promise: rows move when the work shows a cost the
plan did not see.

Proof levels in the "Meanwhile" column: "works in the game" means a real client record backs it; "works on a test
server" means a dedicated-server lab with no player; "unit tests" means no game ran it. Anything else says what is
still open.

## No API yet

| What | What stands in the way | Meanwhile | Planned |
|---|---|---|---|
| Affixes (rolled modifiers on an item) | An item's perks come from its item type, so two items of one type cannot differ in perks. Rolled affixes need per-item data (dev.26, below) plus a modifier engine that applies them on equip ([inventory.md](inventory.md#affixes)) | a fixed set of perks as an item variant of its own | dev.27 |
| Raycast, line of sight, overlap, ground height | No server code; the client's voxel line-of-sight walk is mapped and would be ported to the server | an NPC brain's `Sight` uses distance and faction only ([npc-blocks.md](npc-blocks.md#limits-and-costs)) | dev.28 |
| Writing the camera (cutscenes, shake, field of view) | No write path, native included. Needs RE on whether a server write to the client's camera control moves a vanilla client's camera | a client mod can read the camera ([render.md](../render.md)) | dev.28 |
| Pathfinding queries | Only "go there": `CreatureRef.MoveTo` sets a home, `NpcRuntime.MoveTo` walks; no path or reachability answer ([services/creatures.md](../services/creatures.md)) | none | dev.28 |
| Fog and light | No call sets fog or light; the weather can be chosen since dev.27 (below) | none | not in a release yet |
| Map markers, compass pins, nameplates | Only a quest's marker and waypoint. The game's marker types are mapped, including the player's custom pin | a quest step's `Marker` ([quests.md](quests.md)); on a Kiln client, draw a marker on screen with `Render` (unit tests only) ([render.md](../render.md)) | dev.28 |
| Playing an animation from code; a cancelable "sequence starting" event | `Abilities.PlaySequence` plays a sequence; a mod's own states (dev.26, below) are entered only by a sequence that names them. `SequenceStartedEvent` is observe only | a weapon's `Moves` or a cast's `Animation` naming the state (dev.26) | not in a release yet |
| A mod's own stats, experience values, currencies | No store, no UI ([engines/enshwick.md](../engines/enshwick.md)) | `Progression.AddExperience` adds to the game's own experience ([services/progression.md](../services/progression.md)) | dev.28 |
| Survivor recruit and assign, raising the base limit | Read only (`Villagers`, `WorldProgress.Survivors`); the game's calls need RE ([engines/enshwick.md](../engines/enshwick.md)) | none | dev.29 |
| Slot marks and slot keys (storage mods) | No Kiln equivalent of shroudlink's `Marks` and `SlotKeys` ([engines/shroudlink.md](../engines/shroudlink.md)) | none | dev.27 |
| World programs on a client world | kiln.world registers programs in the server world only ([emf.md](../emf.md)) | `Client.Tick` runs code on the client's main thread at each client-world step ([client.md](../client.md)) | dev.29 |

## There, but limited

| What | What stands in the way | Meanwhile | Planned |
|---|---|---|---|
| Data on one item (dev.26) | `InstanceData` keeps a value on one item through moves, saves, `kill -9` and restored backups ([inventory.md](inventory.md#data-on-one-item-instancedata)). `Persist.Carried` (data that travels with a character between worlds) is not in this release: declaring such a key throws `KilnUnavailableException("saves.instance_data.carried")`. Two identical items swapped where Kiln did not see it (another world, an offline edit) trade their data, and nothing reports it. When Kiln is not sure which of two identical items a value belongs to, the value is set aside, not attached: identical items moved in the last five saves before a player left come back set aside, even after a clean leave; the mod (`InstanceData.Claim` / `Discard`, dev.27) or an admin (`/instances claim` / `discard`) decides then. Plain stacks have no item entity and no data. Caps: 256 records per holder per mod, 64 KB per value. Items in chests work on a test server; a player's inventory has not run with a player | `EntityData` for placed objects and creatures; `PlayerData` / `CharacterData` for a player | dev.27 (`Persist.Carried`, item data synced to Kiln clients) |
| A mod's own player animation states (dev.26) | `assets/player-states.json` adds states to the player's animation graph at boot, each placed like a game state ([animations.md](animations.md#player-states-states-of-your-own-in-the-players-graph), [../services/playeranim.md](../services/playeranim.md)). No hot reload: a change applies from the next start. Definitions from C# (`PlayerAnimStates.Define`) are refused in this release. The player graph's key is reserved: `Assets.Override` / `Register` throw for it and an `assets.json` entry for it is refused. A second cast of a mod's wand state before the first has ended continues its clip instead of restarting it. One clip per state for every weapon family; `SM_Main` has room for six mod states before they nest and lose the neighbour's transitions; overlay machines hold 21 to 30. The mod needs `"side": "both"`, `"clients": "mod"` and its cook on the server too: a client whose merged graph differs from the server's is refused at join (also under `modSync: warn`). Works on a test server with a spawned player character; no client has drawn a state | none | not in a release yet (definitions from code) |
| Weapon moves as a block (dev.26) | `WeaponBlock.Moves` per attack slot: a state to play, the sequence to start from, when the blow lands (`HitAt`), the length; primary and heavy chains ([item-blocks.md](item-blocks.md#moves)). Only the primary and heavy chains link to each other; every other follow-up stays the game's. A wand's `Like` must be one of its premades. An ability's cast refuses `Animation` and `HitAt`. A move whose state name cannot be looked up keeps its `like` state. The capability rows `blocks.weapon_moves` and `blocks.animated_held` exist only after the first item block compiles, so a manifest cannot require them. A clip reworked with `from` that overrides a game clip has not been tried in the game. Lab-checked on a dedicated server; a staff cast with moves, a held block or parry, a shield and picking up a dropped item were not run there, and no player has seen a move | a GUID or `0x` id for `Animation` needs no lookup | dev.29 (remaining building blocks) |
| Choosing the weather (dev.27) | `Time.SetWeather` starts one of the game's own phenomena (its table: clouds, a rain per region, snowy rain) on its layer, for a time or held until `Time.ReleaseWeather`, through the game's own start ([services/time.md](../services/time.md)). The game places a rain at random in its region and lets it drift: a mod cannot put it over a player. The game's debug phenomena (a blizzard among them) are in no layer's roll and are not offered. It does not survive a restart (the game rolls anew after a load; a hold is Kiln's). `WeatherChangedEvent` reads the layers once a step. Works on a test server; no player has seen it | none | not in a release yet (placing a phenomenon) |
| Equip and unequip (dev.27) | `Items.Equip` and `Items.Unequip` run the game's own equip on the server ([services/items.md](../services/items.md#equip-and-unequip-v5-since-020-dev27)). They need kiln.world (the game's equip only runs in a program that iterates the player). A request runs in the next step, after the player's own equip of that step; at most 4 per player per step. A dead player is refused right before the transaction; a request whose player left is refused (the next player in the slot gets the same id). Kiln.Players' `PlayerEquipmentChangedEvent` polls item types and can miss a swap of two items of one type; Kiln's own changes are exact in `EquipChangedEvent`. Equipping an item of another holder (a chest) is refused: move it into the player's inventory first (`Items.Move`). Swapping the whole equipment set is not offered. Works on a test server with a spawned player character; no player has seen the result | none | dev.28 (an equipment-set swap) |
| Capability table (dev.26) | `Capabilities.Is/Get/Why/All` and `CapabilityChangedEvent` answer for sigdb features and services ([../services/caps.md](../services/caps.md)). A row a managed service registers exists only after that service was first used, after manifests were checked, so a manifest's `features` cannot require it: check `Capabilities.Is` at run time. `[RequiresCapability]` marks the members of Kiln.Items, Kiln.Saves' item data, Kiln.PlayerAnim and the weapon-move blocks, but it is documentation: the member's own code throws, nothing checks the attribute. Kiln.Items reports its `items.*` rows when it starts at the first tick; other services still have only their own `Available` property. Unit tests and a test server | `Capabilities.Is(name)` at run time | dev.27 (adoption in every service) |
| Identity types (dev.26) | `EntityRef`, `ItemInstanceRef`, `PlayerRef` and the error rule are in Kiln.Api ([contract.md](contract.md)). Entity sources: players, item entities (Kiln.Items) and every entity kiln.spawn can inspect, from the first tick, not in `OnLoad`. An entity loaded from the save with no `SpawnTime` and no tracker record has serial 0, so `IsAlive` then only says the id exists. `PlayerRef` converts from `Player`, `TalentHolder`, `QuestHolder` and `CharacterKey`, not yet from `NetPeer`, `ChatPlayer` or `PermissionSubject`. Only `PlayerAnimDefineResult` implements `IKilnResult` so far. Refs work on a test server with simulated players; no real player has run them | `PlayerRef.Of`, `Resolve`, `IsOnline` from the first tick | dev.27 (adoption in every service) |
| Offline unit tests (dev.26) | `Kiln.TestKit` runs a mod under `dotnet test` ([unit-tests.md](unit-tests.md)). Only players and saved data are faked; every other native service (spawn, items, combat, content, rendering, hooks…) reports itself unavailable, and a test that needed one is skipped by name. `EntityData` works on player entities only. No network pair: `Kiln.Network` is unavailable offline. Known gap: a service that caches "no table" in a `Lazy` or `static readonly` field (`Kiln.Ui`'s render table; `kiln.net` at the first channel) asks once per process, so a later test using it can pass where it should be skipped. Unit tests and one test-server parity run; Windows not run | read the service's `Available` in the test | dev.27 (fake world, recording fakes) |
| Typed game data (dev.26) | `Kiln.Ecs` in Kiln.Game (`KilnServices` `Game`) has typed structs for the game's 687 components and 132 events, checked against the running game before the first read ([../typegen.md](../typegen.md#4-typed-access-kilnecs)). Reads only: writes are still raw (`World.TryWrite`). An enum constant the compiler folds into a number is not stamped, so a renumbered value is not caught at load. Typed reads equal the raw bytes on a test server for 118 components; the other 569 had no live entity there, and the client side has not run | `Reflected` values by name ([services/types.md](../services/types.md)) | dev.27 (`World.Update<T>`, typed program access) |
| Lab and test helpers on service classes (dev.26) | `Rules.Simulate`, `QuestInput`, `Knowledge.LabRecord`, `GameTree.Simulate` and `Lab*`, `CreatureRef.ForceReady` and others are `[Experimental("KILNX001")]` and hidden: calling one is a build error until the project adds `KILNX001` to `NoWarn`, and they may change without notice | `NoWarn` for a lab-only project | not in a release yet |
| Writes the game saves and sends | `World.TryWrite` and `ReflectedValue` are raw stores the game does not mark written: a player-free test showed the save skips them on a container a save already wrote. Attribute writes are not marked written for saving either. Only kiln.items uses the tracked path, for water ([services/items.md](../services/items.md)) | `Items.Fuel` for water (works on a test server); a Kiln service call where one exists | dev.27 |
| Systems | `GameSystems.Hook(name, before, after)` and on/off only: no Replace, no per-entity wrap, no typed views ([ecs-programs.md](ecs-programs.md)) | a world program of your own ([ecs-programs.md](ecs-programs.md)) | dev.28 |
| Kiln natives in Impact programs | A native suspends the program for one step, and only programs a mod clones or writes call them ([impact.md](impact.md)) | none | dev.28 |
| Hooks from C# | `Hooks.Detour` sees the first four integer arguments; floats need `Hooks.Mid` or a native mod's `raw_detour`. Slots are never freed; from dev.26 a re-install by the same mod, kind and address reuses its slot, also across a hot reload (test server), but each new address takes one ([services/hooks.md](../services/hooks.md#limits-and-failures)) | `Hooks.Mid`; a [native mod](../native-mods.md) | dev.28 (typed hooks with floats) |
| Writes that raise no event | Attribute writes, `Combat.SetHealth` / `SetInvulnerable`, `CreatureRef` setters, content `Set` / `Apply` / `Revert`, `Time.SetSpeed` / `SetCycle` and `World.TryWrite` post nothing (`Time.ResetWeather` and `SetWeather` show in `WeatherChangedEvent` since dev.27) ([../events.md](../events.md)) | none: a mod that needs to know has to poll | dev.27 (a change event for each of Kiln's own writes) |
| Events that cannot be canceled | Death, item pickup, a player's build edits and equipment changes are reported after the fact | death: cancel or lower the lethal `EntityHurtEvent` ([services/combat.md](../services/combat.md)); build edits: `Gameplay.Protect` zones (client check open) ([services/gameplay.md](../services/gameplay.md#protection-zones)) | dev.28 |
| Definitions from code | Mods load after the game's registries close. Since dev.27 Kiln.Sdk bakes C# quests (with their NPCs and dialogues), `GameTree.Define` nodes, VFX and material blocks into the mod at build, so these are in from the first start ([baked.md](baked.md); works on a test server, a client not checked). Still from the next start: a mod that does not load without the game (statuses, effects, items, spells and talent blocks lower onto kiln.assets and kiln.content, which the build's harness lacks), NPC blocks, world-table blocks and crafting props from C#. World-program declarations are `kiln.programs.json`, a file: in from the first start | put the rest in `blocks/*.json`, `quests/*.json` or `skills/*.json`: those are in from the first start (works on a test server) | dev.28 (`Mod.OnBoot`) |
| UI blocks | No text fields, tables, tabs, images or trees; no values from the game's world; no state of a window's own; a block's `command` does not reach a joined server ([ui-blocks.md](ui-blocks.md#what-it-does-not-do)) | `Ui.Window` and `Ui.Screen` in C# ([../ui.md](../ui.md)); Kiln's own windows have opened in the game | dev.28 |
| A native plugin's `on_unload` at exit (dev.26) | Called once at a normal exit with code 0, under Wine only by default: off on native Windows unless `kiln.json` has `"unloadAtExit": "on"`, which has never run. Proven for a dedicated server stopped with SIGINT on a test server; the client's quit is not confirmed. Not called on a kill, a crash or any non-zero exit ([../native-mods.md](../native-mods.md)) | write state as you go, not only at exit | not in a release yet |
| Event filters (dev.27) | `Events.On<T>(handler, EventFilter.ForEntity(e))` filters by entity on events that are `IEntityEvent` (Kiln.Combat's); kiln.combat then holds only the watched entities' hits ([../events.md](../events.md)). No filter by template or component, none for `[Subscribe]` methods, and only kiln.combat's hold uses the filters: kiln.abilities' instance hold and kiln.playerstate's client-action hold still hold for every entity while anyone listens. Works on a test server (Kiln's game hits); the game's own hits from a player's swing have not run through it | check the template in the handler | not in a release yet |
| Kick, ban, login refusal (dev.27) | `Players.Kick`, Kiln's ban list (`Bans`, `/ban`) and the cancelable `PlayerLoginEvent` refuse a connection with the game's login failure ([../services/players.md](../services/players.md#kick-and-ban-dev27)). Kiln's list is not the game's own ban list. A Kiln client is not held at the gate, so a banned Kiln player can stand in the world for a second or two first. The kick path ran on a test server with fake clients only: no real player has been kicked or banned, and it is not known yet whether the login failure takes a player who is already in the world out of it | guided checks `kick-test/players.kick`, `players.ban` | not in a release yet |
| Player aim (dev.27) | `Player.Aim` is the camera the player's client sent with its input: third person, so the ray starts at the camera behind the character ([../services/player-state.md](../services/player-state.md#aim-dev27)). As trustworthy as the client. A scripted ability's `Forward` target still points along the body's yaw. On a joined client only the own player. Works on a test server with a camera written into a player entity's input; no real client's camera has been read yet (guided check `players.aim`) | none | not in a release yet |
| Buffs from C# (dev.27) | `Abilities.ApplyBuff`, `Abilities.RemoveBuff` and `Abilities.BuffsOf` work on players, creatures and NPCs on the server ([../services/abilities.md](../services/abilities.md)). A removal is answered about two steps later (it runs in a game program); a buff is named by its GUID or its id, not by a name. `BuffsOf` is empty on a joined client: the game keeps buffs on the server. Works on a test server, on a creature and on a player-template entity; a real client has not shown the buff icon go (guided check `abilities.remove-buff`) | none | not in a release yet |
| Station menus with tabs of their own | A station's menu uses its kind's tabs, or `Menu.Like`'s ([world-blocks.md](world-blocks.md)) | `Menu.Like` an existing station | dev.29 |
| Per-use durability on tools | Only a torch burns down by a number of the item's own; the game wears other tools by the world's durability setting, so `Durability` on them is refused ([item-blocks.md](item-blocks.md)) | none | dev.29 |
| Cloth and chains on a model | The model cook does not write them ([models.md](models.md)) | rigid or skinned parts | dev.29 |
| A roster NPC with a body of its own; villager routines | A friendly NPC's body is a game NPC's for now; routines need hooks on the game's task choice ([npc-blocks.md](npc-blocks.md#limits-and-costs)) | `Bodies.Villager`, `Bodies.Fisher` | dev.29 |
| A block kind of your own | `Kiln.Blocks` uses the internals of seven services; there is no public way to add a kind ([blocks.md](blocks.md)) | compose the existing blocks | dev.29 |
| Content sync to joined clients | Loot and drop tables are rolled on the server and not sent; PNG icons are not sent; a changed reference of a game item in a list field (per-body or pickup model lists) is not sent ([../sync.md](../sync.md), [services/content.md](../services/content.md)) | ship the mod to the client (`clients: mod`) or a modpack | not in a release yet |

## Hard caps

Values read from the code of dev.24. Where the code counts the game's data at start (skill points, material ids), the
value is the count for the current game build.

| Access lists per world program | templates 8, read and write 42, singletons 64 per list, other templates 9, other accessors 92, event inputs and outputs 24 | the game's scheduler ([ecs-programs.md](ecs-programs.md)) | not in a release yet |

| Waiting item data records (dev.26) | dropped after 3 sessions without their item | Kiln.Saves' instance store | not in a release yet |
| Global transitions per player state machine (dev.26) | 34 per machine; a full-body machine past it nests its mod states, an overlay machine holds 21 to 30 mod states and refuses the rest | the game's graph format, kiln.playeranim's merge ([animations.md](animations.md#limits)) | not in a release yet |
